# T-01: ratings: add src/ratings/notch.mjs (RATING_SCALE + notchChange) with TDD unit tests

## User story
As a developer building the REQ-06-02 notch calculator and Ind. 11, 12 and 13, I want a pure function that gives the signed notch change between two credit ratings, so that every indicator measures downgrades and upgrades on the same 19-step scale.

## What to build
- `src/ratings/notch.mjs`: a pure Node 18+ ESM module with no dependencies, no I/O imports and no `console` calls. It has exactly two named exports:
  - `RATING_SCALE`: `Object.freeze(['AAA','AA+','AA','AA-','A+','A','A-','BBB+','BBB','BBB-','BB+','BB','BB-','B+','B','B-','CCC+','CCC','CCC-'])`.
  - `notchChange(previous, current)`: returns `index(current) - index(previous)`. It accepts only primitive strings (`typeof === 'string'`), applies `trim()` and then `toUpperCase()` (not `toLocaleUpperCase()`), and looks the result up in `RATING_SCALE`. Every invalid argument throws `RangeError`. `previous` is checked first. The message names the argument and its value, and building it must never throw. Extra arguments are ignored.
- `test/ratings/notch.test.mjs`: written test-first with `node:test` and `node:assert/strict`. It covers AC-1 to AC-12 and AC-14. AC-13 is optional here.
- `package.json`: do not change it.

## Acceptance criteria
1. **AC-1:** Given the module is imported, when `RATING_SCALE` is read, then it deep-equals the 19-entry list above, its length is `19`, `[0]==='AAA'`, `[7]==='BBB+'`, `[10]==='BB+'`, `[18]==='CCC-'`, every entry is upper-case and `new Set(RATING_SCALE).size === 19`.
2. **AC-2:** Given the module is imported, when it is inspected, then `Array.isArray(RATING_SCALE)` and `Object.isFrozen(RATING_SCALE)` are both `true`. When `RATING_SCALE.push('D')` or `RATING_SCALE[0]='X'` runs, then each throws `TypeError`. Afterwards the length is still `19`, `[0]` is still `'AAA'` and `notchChange('AAA','CCC-')` is still `18`.
3. **AC-3:** Given previous `'BBB+'` and current `'BB+'`, when `notchChange('BBB+','BB+')` is called, then it returns `3`.
4. **AC-4:** Given previous `'BB+'` and current `'BBB+'`, when `notchChange('BB+','BBB+')` is called, then it returns `-3`.
5. **AC-5:** Given `'A'` and `'A'`, when `notchChange('A','A')` is called, then `Object.is(result, 0)` is `true` (the result is not `-0`). For every `r` in `RATING_SCALE`, `Object.is(notchChange(r,r), 0)` is also `true`.
6. **AC-6:** Given neighbouring ratings and the two ends of the scale, when `notchChange` is called, then the results are: `AAA→AA+` = `1`, `AA+→AAA` = `-1`, `BBB-→BB+` = `1`, `BB+→BBB-` = `-1`, `CCC→CCC-` = `1`, `AAA→CCC-` = `18`, `CCC-→AAA` = `-18`.
7. **AC-7:** Given every `i, j` in 0..18 (361 pairs), when `notchChange(RATING_SCALE[i], RATING_SCALE[j])` is called, then it returns exactly `j - i`, the result is an integer in [-18, 18], and `notchChange(a,b) === -notchChange(b,a)` whenever `a !== b`.
8. **AC-8:** Given whitespace that `trim()` removes at the start or end of an argument, when `notchChange` is called, then the whitespace is ignored: `(' BBB+ ','BB+')` = `3`, `('\tBB+\n','BBB+')` = `-3`, `(' A ','A')` = `0`, `('AAA','  CCC-\r\n')` = `18`.
9. **AC-9:** Given lower-case or mixed-case input, when `notchChange` is called, then case is ignored: `('bbb+','bb+')` = `3`, `('Aa-','aa+')` = `-2`, `('ccc-','aaa')` = `-18`, `(' bBb- ','BB+')` = `1`.
10. **AC-10:** Given a string that is not in the scale after trim and upper-case, in either position, when `notchChange` is called, then it throws `RangeError`. Values: `'D'`, `'NR'`, `'AAA+'`, `'BB++'`, `'C'`, `'BBB +'`, `'BBB−'`, `'Baa1'`, `'BBB+ (neg)'`. For example, `('D','A')`, `('A','D')` and `('BBB +','BB+')` all throw `RangeError`.
11. **AC-11:** Given `''`, `' '`, `'\t\n'` or `' '` (NBSP only) in either position, when `notchChange` is called, then it throws `RangeError`. For example, `('', 'A')` and `('A','   ')` both throw.
12. **AC-12:** Given any of `undefined`, `null`, `0`, `7`, `NaN`, `true`, `1n`, `Symbol('A')`, `{}`, `Object.create(null)`, `['A']`, `() => 'A'`, `new String('A')`, `new String('BBB+')` in either position, when `notchChange` is called, then it throws `RangeError`, never `TypeError` and never a return value. `notchChange()` and `notchChange('A')` also throw `RangeError`.
13. **AC-13:** Given invalid input, when `notchChange` throws, then:
    - `('ZZZ','QQQ')` gives a `RangeError` whose message contains `previous` and `ZZZ`.
    - `('A','QQQ')` gives a message that contains `current` and `QQQ`.
    - `(Symbol('x'),'A')` gives a `RangeError`, not a `TypeError` raised while the message is built.
    - Unit tests need only assert the error type. QA checks the wording by command.
14. **AC-14:**
    - Given the module is imported, when `notchChange('BBB+','BB+')` is called 100 times with stdout and stderr captured, then nothing is written and every call returns `3`.
    - Given `p=' bbb+ '` and `c='BB+'`, after the call they are still `' bbb+ '` and `'BB+'`.
    - `src/ratings/notch.mjs` has no `import` of `node:fs`, `node:net`, `node:http` or `node:child_process` (nor any other I/O module) and no `console.` call.
15. **AC-15:**
    - Given the delivered branch, when `node --test` is run from the repo root, then it exits `0`.
    - `test/ratings/notch.test.mjs` exists, imports `node:test` and `node:assert/strict`, and covers AC-1 to AC-12 and AC-14.
    - `package.json` has no `dependencies` and no `devDependencies` key and is otherwise unchanged.

## Edge cases
- **Check order:** when both arguments are invalid, the error is about `previous`. `current` is checked only after `previous` passes.
- **String objects:** do the `typeof` check before any coercion. `new String('A')` must throw `RangeError` even though `String(new String('A'))` gives `'A'`.
- **Message building:** a template literal or `+` on a `Symbol` or on `Object.create(null)` throws `TypeError`. Use a safe describer:
  - string: `JSON.stringify(v)`
  - symbol: `v.toString()`
  - bigint: `String(v) + 'n'`
  - anything else: `String(v)` inside try/catch, falling back to `Object.prototype.toString.call(v)`.
- **Whitespace:** `trim()` removes space, tab, CR, LF, NBSP and BOM at either end, so those are accepted. Whitespace inside a rating (`'BBB +'`) is not removed, so the value is rejected.
- **Look-alike characters:** the Unicode minus `−` is not ASCII `-`, so it is rejected. There is no normalisation step.
- **Locale:** use `toUpperCase()`, not `toLocaleUpperCase()`.
- **Extra arguments:** they are ignored. `notchChange('A','A','junk')` returns `0`.
- **Signed zero:** the result for equal ratings is always `+0`.
- **Node version:** use Node 18 APIs only. Do not use `toSorted`, `toReversed`, `with` or `Object.groupBy`.
