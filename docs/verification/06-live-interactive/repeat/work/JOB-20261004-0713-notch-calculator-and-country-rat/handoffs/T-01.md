- Wrote the unit tests first (`test/unit/ratings/notch.test.mjs`) and saw them fail because the module did not exist (RED). Then implemented `src/ratings/notch.mjs` (GREEN, 156 tests pass).
- `RATING_SCALE`: `Object.freeze` array of the 19 ratings, best first.
- A private module-level `Map` (rating -> index) is built from the scale. A single private helper `ratingIndex(value, name)` accepts only strings, trims and upper-cases them, then looks them up with `Map.get`. It throws `RangeError` otherwise.
- The error message names the parameter (`previous` or `current`) and a safe representation of the value. Strings go through `JSON.stringify`. Other values use `String()` in a try/catch, falling back to `Object.prototype.toString.call`, then `typeof`. Building the message never throws (Symbol, null-prototype objects, bigint and a throwing `toString` are covered by tests).
- `previous` is validated first, so when both are invalid only `previous` is named.
- `notchChange` is plain index subtraction (`to - from`), so unchanged is +0.
- `notchCalculator` returns a new plain object `{notches, direction, wl}` with WL 0 for notches <= 1, 1 for 2 and 2 for 3 or more. The WL mapping is inline, not a shared helper (C2, C6).
- JSDoc on all three exports. No default export. No imports in the source.
