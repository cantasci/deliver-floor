# T-02: Indicator 12 countryRatingChangeWl in src/indicators/countryRating.mjs

## User story
As a credit analyst (through later POC screens) and as the Watchlist indicator engine, I want to give a previous and a current country rating and get the Indicator 12 WL (0, 1 or 2), so that a country downgrade raises the watchlist level by its own thresholds, not by the calculator's (REQ-03-12, C3).

What to build: create `src/indicators/countryRating.mjs` with exactly one named export, `countryRatingChangeWl(previous, current)`. It computes `n = notchChange(previous, current)` (imported from `'../ratings/notch.mjs'`) and returns the literal `0` when n <= 0, `1` when n === 1 and `2` when n >= 2. No rating list, no map, no validation of its own, no catching or wrapping of errors. Dev unit tests in `test/unit/indicators/*.test.mjs`; QA integration tests in `test/integration/indicators/*.test.mjs`. `src/ratings/` must not be modified.

## Edge cases
- Threshold boundaries n = -18, -1, 0, 1, 2, 3, 18 give 0, 0, 0, 1, 2, 2, 2. A WL above 2 is never returned.
- -0 cannot happen because the function returns the literals 0, 1 and 2. Do not reuse calculator thresholds or a clamp (AC-16).
- Normalisation and validation come only from `notchChange`: `" bbb+"` is valid, `"​BBB"` throws RangeError, `new String("A")` throws RangeError, `"__proto__"` throws RangeError.
- The error reaches the caller unchanged: no try/catch, no re-throw with a new message, no fallback WL.
- Extra arguments are ignored. Missing current (`countryRatingChangeWl("A")`) throws RangeError naming `current`.
- No state is kept; results do not depend on call order.
