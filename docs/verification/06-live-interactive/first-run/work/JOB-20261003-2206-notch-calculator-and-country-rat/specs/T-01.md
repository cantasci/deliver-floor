# T-01: Ratings module: RATING_SCALE, notchChange, notchCalculator (REQ-06-02)

## User story
As a POC module that needs to read rating changes (and as the analyst who picks the previous and current rating), I want a pure notch calculator over the 19-step rating scale, so that every rating change gives the same signed notch count, direction and WL.

## What to build
- `src/ratings/notch.mjs`: pure and synchronous, no imports, no I/O, no `console`. Exports exactly `RATING_SCALE`, `notchChange`, `notchCalculator`, each with inline JSDoc. One private helper checks input: if `typeof value !== "string"` throw `RangeError`; otherwise trim, uppercase, look up in `RATING_SCALE`; not found -> `RangeError` with a message naming the value, e.g. `Unknown rating: "BB "`.
- `test/ratings/notch.test.mjs`: written first (TDD), `node:test` + `node:assert/strict`.

## Edge cases
- Non-strings (null, undefined, numbers, objects, arrays, `new String("BBB")`) throw `RangeError`; the type check runs before `.trim()`.
- Whitespace follows `String.prototype.trim`; inner whitespace (`"BBB +"`, `"B BB"`) throws `RangeError`.
- Only ASCII `+`/`-` are valid; U+2212 and U+2013 throw `RangeError`.
- Off-scale ratings (CC, C, D, SD, NR), Moody's notation (Baa1) and invented notches (AAA+, CCC--) throw `RangeError`; nothing is mapped to a nearby rating.
- Error message names the failing value; tests must not check the text.
- Scale ends: AAA→AAA and CCC-→CCC- = +0; max ±18.
- wl boundaries: n=1 → 0, n=2 → 1, n=3 → 2; any negative n → 0.
- Result object has exactly three keys.
