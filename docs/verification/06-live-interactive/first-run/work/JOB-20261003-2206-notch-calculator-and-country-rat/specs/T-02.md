# T-02: Indicator 12: countryRatingChangeWl built on notchChange (REQ-03-12)

## User story
As a POC module that scores the Watchlist (and as the analyst who enters or edits the previous and current country rating), I want Indicator 12 to map a country rating change to WL 0, 1 or 2, so that a sovereign downgrade raises the client's Watchlist level by its own thresholds.

## Traces to
AC-4 (indicator part), AC-5 (indicator part), AC-10, AC-11, AC-12, AC-13, AC-14 (indicator part), AC-15. REQ-03-12. Clarifications C1, C3, C6, C7, C8. Depends on T-01 (the card context calls it "B1").

## What to build
- `src/indicators/countryRating.mjs`: pure, synchronous, inline JSDoc. Exports exactly `countryRatingChangeWl(previous, current)`. Only import: `import { notchChange } from "../ratings/notch.mjs"`. Rule: n = `notchChange(previous, current)`; n <= 0 → 0, n === 1 → 1, n >= 2 → 2. Does not catch or wrap the `RangeError` from `notchChange`; does not use `notchCalculator`.
- `test/indicators/countryRating.test.mjs`: written first (TDD), `node:test` + `node:assert/strict`. The test file (not the source) may import `notchCalculator` and `RATING_SCALE`.
- `src/ratings/**` is not modified.

## Acceptance criteria
1. (AC-10) Given a country rating downgrade, when `countryRatingChangeWl` is called, then ("A","A-") = 1, ("BBB+","BBB-") = 2, ("BBB+","BB+") = 2, ("AAA","CCC-") = 2.
2. (AC-11) Given an upgrade or unchanged rating, then ("A-","A"), ("BB+","BBB+"), ("CCC-","AAA"), ("A","A"), ("CCC-","CCC-") each return 0, with `Object.is(result, 0) === true`.
3. (AC-4) Given input differing only in case or leading/trailing whitespace, then `countryRatingChangeWl(" a ","a-") === 1`, `countryRatingChangeWl("bbb+"," BB+ ") === 2`, `countryRatingChangeWl("\tA\n","a") === 0`.
4. (AC-5) Given an invalid value in `previous` with `current = "BBB"`, then in `current` with `previous = "BBB"`, then in both, `assert.throws(fn, RangeError)` passes for each of: `""`, `"   "`, `"CC"`, `"C"`, `"D"`, `"SD"`, `"NR"`, `"Baa1"`, `"BBB +"`, `"BBB−"` (U+2212), `"AAA+"`, `null`, `undefined`, `7`, `{}`, `["BBB"]`; never TypeError, never a returned value. Tests check the error type only.
5. (AC-12, C6) Given the same pair, `notchCalculator(p,c).wl` and `countryRatingChangeWl(p,c)` are: A→A- = 0 and 1; BBB+→BBB- = 1 and 2; BBB+→BB+ = 2 and 2; AAA→CCC- = 2 and 2; BB+→BBB+ = 0 and 0; A→A = 0 and 0.
6. (AC-12, AC-10) Given all 361 pairs (p, c) of `RATING_SCALE` x `RATING_SCALE`, with `w = countryRatingChangeWl(p, c)` and `n = notchChange(p, c)`, then `w === (n <= 0 ? 0 : n === 1 ? 1 : 2)` and `[0,1,2].includes(w)`.
7. (AC-13, C7) Given the pre-filled pair ("BBB","BBB-") giving 1, when the analyst edits current to "BB", then `countryRatingChangeWl("BBB","BB")` returns 2; calling `countryRatingChangeWl("BBB","BBB-")` again still returns 1 (no state).
8. (AC-13) `countryRatingChangeWl.length === 2`, `notchChange.length === 2`, `notchCalculator.length === 2` (no override parameter).
9. (AC-14) Given `const m = await import("../../src/indicators/countryRating.mjs")`, `Object.keys(m)` deep-equals `["countryRatingChangeWl"]`.
10. (AC-14, C6, C8) Given the source of `src/indicators/countryRating.mjs` read as text, its only import is from `"../ratings/notch.mjs"` and names only `notchChange`; it does not contain `notchCalculator`, any `node:` import, `console` or `process`; calling the function writes nothing to stdout or stderr.
11. (AC-15) Given the job branch with both test files, `node --test` from the repo root exits 0 with 0 failures, tests from both `test/ratings/notch.test.mjs` and `test/indicators/countryRating.test.mjs` run, `package.json` has no `dependencies` or `devDependencies` key, and no commit carries AI attribution.

## Edge cases
- Boundaries: n = 0 → 0, 1 → 1, 2 → 2, 3 → 2, 18 → 2, -1/-2/-3/-18 → 0.
- Unchanged returns +0, never -0.
- Invalid input follows T-01: `notchChange` throws `RangeError` and it propagates unchanged; no try/catch, re-wrap, fallback or default (e.g. 0).
- U+2212 and en dash, inner whitespace, off-scale ratings and non-strings (incl. `new String("BBB")`) throw `RangeError`.
- The trap (C6): deriving from `notchCalculator().wl` would give 0 for A→A- and 1 for BBB+→BBB-; criteria 5 and 10 catch this.
- Return type is a plain number from {0, 1, 2}.
