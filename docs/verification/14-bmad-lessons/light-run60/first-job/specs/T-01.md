# T-01: Indicator 13: externalRatingChangeWl(previous, current) on notchChange

## User story
As a credit-monitoring analyst, I want a client's external rating downgrade turned into a Watchlist level automatically (2 notches → WL 1, 3 or more → WL 2), so that a deteriorating client is flagged without a manual notch count.

## Traces to
AC-1, AC-2, AC-3, AC-4, AC-5, AC-6, AC-7 · REQ-03-13 · Clarifications 1–3 · readiness CON-interface, CON-errors, CON-compat, NFR-security, TST-strategy

## Acceptance criteria
1. (AC-7) Given the file `src/indicators/externalRating.mjs`, when it is imported, then it exports a named function `externalRatingChangeWl(previous, current)`. The module imports `notchChange` from `../ratings/notch.mjs`, contains no rating-code literals or scale array, and imports nothing else.
2. (AC-1) Given valid ratings with `notchChange(previous, current) === 2`, when `externalRatingChangeWl(previous, current)` is called, then it returns `1`. For example, `("BBB+","BBB-")` → 1, `("AAA","AA")` → 1, `("CCC+","CCC-")` → 1.
3. (AC-2) Given valid ratings with `notchChange(previous, current) >= 3`, when it is called, then it returns `2`. For example, `("BBB+","BB+")` → 2, `("B-","CCC-")` → 2, `("AAA","CCC-")` → 2.
4. (AC-3) Given valid ratings with `notchChange(previous, current) <= 1` (a 1-notch downgrade, unchanged or any upgrade), when it is called, then it returns `0`. For example, `("BBB+","BBB")` → 0, `("AA","AA")` → 0, `("BB","BBB")` → 0, `("BBB-","BBB+")` → 0, `("CCC-","AAA")` → 0.
5. (AC-1/2/3, full scale) Given every ordered pair `(RATING_SCALE[i], RATING_SCALE[j])`, which is 361 pairs, when it is called, then the result equals `d >= 3 ? 2 : d === 2 ? 1 : 0` with `d = j − i`. The counts are WL 1 = 17, WL 2 = 136 and WL 0 = 208.
6. (AC-4) Given ratings with surrounding whitespace or in lower or mixed case, when it is called, then they are read as the trimmed, upper-cased code. For example, `(" bbb+ ","bb+")` → 2, `("bbb+","Bbb-")` → 1, `("aa","AA")` → 0.
7. (AC-5) Given an argument that is not on the scale after trim and upper-casing, when it is called, then it throws `RangeError` (the error `notchChange` throws, not caught or wrapped) and returns no value.
8. (AC-7) Given any valid pair, when it is called, then the result is of type `number` (strict equality against `0`, `1` or `2`; never a string, boolean or object).
9. (AC-6) Given the card's branch, when `git diff --name-only main...HEAD` is run, then only `src/indicators/externalRating.mjs`, `test/unit/indicators/externalRating.test.mjs` (dev) and `test/integration/indicators/externalRating.int.test.mjs` (QA) appear, and `npm test` passes, including the existing `notch` and `countryRating` tests, unchanged.

## Edge cases
- Top of the scale: `("AAA","AA+")` → 0 (1 notch), `("AAA","AA")` → 1, `("AAA","AA-")` → 2.
- Bottom of the scale: `("CCC","CCC-")` → 0, `("CCC+","CCC-")` → 1, `("B-","CCC-")` → 2.
- Maximum span: `("AAA","CCC-")` → 2, and the reverse `("CCC-","AAA")` → 0.
- Unchanged at each end: `("AAA","AAA")` → 0, `("CCC-","CCC-")` → 0.
- Empty, whitespace-only, `null` or `undefined` (including a missing second argument): `RangeError`.
- Codes off this scale (`D`, `SD`, `NR`, `WD`, Moody's `Baa1`), inner whitespace (`"A +"`) and a non-string number (`5`): `RangeError`.
- When both arguments are invalid, a `RangeError` is thrown; which argument the message names is not asserted.
