# T-01: Rating scale and notch calculator (src/ratings/notch.mjs)

## User story
As a developer of the Watchlist POC, I want one shared rating scale plus a signed notch change and a notch calculator (notches, direction, WL), so every screen and indicator comparing two ratings gets the same WL under the Indicator 13 thresholds.

## Traces to
AC-1, AC-2, AC-3, AC-6, AC-7 in full. AC-4, AC-5 for `notchChange`/`notchCalculator` (T-02 covers `countryRatingChangeWl`). AC-10 calculator part. AC-11 notch.mjs part.

## Acceptance criteria
Each criterion reads: Given the inputs named, when the function is called, then the result or error is as stated.
Scale indices (C1): AAA 0, AA+ 1, AA 2, AA- 3, A+ 4, A 5, A- 6, BBB+ 7, BBB 8, BBB- 9, BB+ 10, BB 11, BB- 12, B+ 13, B 14, B- 15, CCC+ 16, CCC 17, CCC- 18.

1. (AC-1) `RATING_SCALE` deep-strict-equals ["AAA","AA+","AA","AA-","A+","A","A-","BBB+","BBB","BBB-","BB+","BB","BB-","B+","B","B-","CCC+","CCC","CCC-"]; length 19; [0]==="AAA"; [18]==="CCC-"; entries upper-case, no whitespace; no CC/C/D/SD/NR.
2. (AC-2) `Object.isFrozen(RATING_SCALE)` is true; `push("D")`, `[0]="X"`, `reverse()` each throw TypeError (ESM strict); the scale is unchanged afterwards and `notchChange("AAA","AA+") === 1`.
3. (AC-3) `notchChange(previous,current)` = index(current) − index(previous), integer. ("BBB+","BB+")→3, ("BBB+","BBB-")→2, ("BBB+","BBB")→1, ("BBB","BBB")→0 with Object.is(r,0) (never -0), ("BB+","BBB+")→-3, ("AAA","CCC-")→18, ("CCC-","AAA")→-18, ("AAA","AA+")→1, ("CCC","CCC-")→1.
4. (AC-4) Input differing from a scale value only in case or leading/trailing `trim()` whitespace is treated as that value, in either position: notchChange("bbb+","BB+")→3; ("  BBB+\t","\nbb+ ")→3; (" Bbb- ","bbb-")→0; notchCalculator("aaa","ccc-")→{notches:18,direction:"downgrade",wl:2}; notchCalculator(" bbb ","BBB")→{notches:0,direction:"unchanged",wl:0}.
5. (AC-5) Any argument not on the scale after trim+upper-case, as previous (current="BBB") or as current (previous="BBB"), to notchChange and notchCalculator → throws, `instanceof RangeError`, never TypeError. Values: "", "   ", "\t\n", "D","SD","NR","CC","C","AAA+","BBB--","7","​BBB", "B B B+","BBB +","BBB +","BBB+ (sf)", null, undefined, 7, 0, NaN, true, {}, ["BBB+"], new String("BBB+"), {toString(){return "BBB+"}}, Symbol("BBB"), Object.create(null).
6. (AC-5, X-error-message) notchChange("X","Y") and notchCalculator("X","Y") → RangeError whose message contains "previous" and "X". Only test on message text.
7. (AC-6) Downgrade: notchCalculator returns exactly keys notches, direction, wl; notches===notchChange; direction "downgrade"; wl 0 for 1 notch, 1 for 2, 2 for 3+. ("BBB+","BB+")→{3,"downgrade",2} (C2, not 2/WL1); ("BBB+","BBB-")→{2,"downgrade",1}; ("BBB+","BBB")→{1,"downgrade",0} (C6); ("AAA","CCC-")→{18,"downgrade",2}; ("A","BBB+")→{2,"downgrade",1}.
8. (AC-7) Upgrade → {notches:<negative>,direction:"upgrade",wl:0}; unchanged → {0,"unchanged",0}; Object.is(notches,0), Object.is(wl,0). ("BB+","BBB+")→-3; ("BBB-","BBB+")→-2; ("CCC-","AAA")→-18; ("BBB","BBB")→0.
9. (AC-10) All 361 pairs: notchCalculator(p,c) deepStrictEquals {notches:n, direction by sign, wl: n>=3?2:n===2?1:0}; notchChange(c,p)===-n; diagonal Object.is(n,0).
10. (AC-11) Module exports typeof "object","function","function"; calls write nothing to stdout/stderr; package.json unchanged vs main; no I/O imports (fs, net, http, child_process, …, with or without node:), no `console.`, no module-level let/var; `node --test test/ratings/notch.test.mjs` passes.

## Edge cases
- WL boundaries n=1→0, 2→1, 3→2, 18→2 (capped); upgrades → 0. No helper shared with Indicator 12.
- No -0: do not use Math.sign, negation or -(a-b).
- trim() whitespace accepted: space, \t, \n, \r, \v, \f, NBSP  , BOM ﻿,  , 　. Rejected: ​, interior whitespace.
- No coercion: check typeof x === "string" before .trim().
- The error message must not throw while built (Symbol, Object.create(null) → still RangeError).
- notchChange() and notchChange("BBB") → RangeError. indexOf -1 never used as an index; no exported mutable lookup.
- Each call returns a new object; arguments not mutated.
