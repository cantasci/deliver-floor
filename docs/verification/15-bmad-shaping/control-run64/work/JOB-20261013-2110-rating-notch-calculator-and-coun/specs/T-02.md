# T-02: Indicator 12 country rating change WL (src/indicators/countryRating.mjs)

**What to build:** a new pure ES module `src/indicators/countryRating.mjs`. Its only import is `notchChange` from `../ratings/notch.mjs` (T-01). It exports `countryRatingChangeWl(previous, current)`, which returns the number 0, 1 or 2 by the Ind. 12 rule:

| `notchChange(previous, current)` | WL |
| --- | --- |
| 1 | 1 |
| 2 or more | 2 |
| 0 or negative | 0 |

Validation is left to `notchChange`, so every invalid input throws `RangeError`. The function must not catch, wrap or replace that error. It declares exactly two parameters. Unit tests go in `test/indicators/countryRating.test.mjs`. Do not change `src/ratings/notch.mjs`, and do not reuse `notchCalculator` (it follows the Ind. 13 rule).

## User story
As a credit analyst, I want the WL for Ind. 12 (Country rating change) computed from the previous and current sovereign rating I confirmed or edited, so that the indicator mirrors the Excel dropdown rule exactly and no country downgrade is missed.

## Acceptance criteria
1. AC-9 [P0] — a wrong Ind. 12 WL rates a client wrongly for compliance (the Must requirement): Given `import { countryRatingChangeWl } from "../../src/indicators/countryRating.mjs"`, when it is called, then `assert.strictEqual` gives a number:
   - ("BBB","BBB-") → 1; ("BBB-","BB+") → 1
   - ("BBB","BB+") → 2; ("BBB+","BB+") → 2; ("AAA","CCC-") → 2
   - ("AA","AA") → 0; ("BB+","BBB-") → 0; ("BB","BBB") → 0; ("CCC-","AAA") → 0
2. AC-10 [P0] — a pair outside the examples gets a wrong WL, with no workaround: Given every ordered pair (p, c) of the 361 pairs from `RATING_SCALE`, when `countryRatingChangeWl(p, c)` is called, then it returns 1 when `notchChange(p, c) === 1`, 2 when it is `>= 2`, and 0 otherwise. The result is always one of 0, 1, 2 (`typeof "number"`).
3. AC-11 [P0] — bad input that returns 0 hides a downgrade: Given each `v` in INVALID, when `countryRatingChangeWl(v, "BBB")` or `countryRatingChangeWl("BBB", v)` is called, then it throws `RangeError`. `countryRatingChangeWl()` with no arguments throws `RangeError` too.
4. AC-12 [P1] — a stale or stored result would ignore the analyst's edit; the workaround is to enter the WL by hand: Given the analyst edits the current rating, when these calls run in order, then:
   - ("BBB","BBB-") → 1
   - after the edit to "BB", ("BBB","BB") → 2
   - edited back, ("BBB","BBB") → 0
   - ("BBB","BBB-") again → 1 (nothing is kept between calls)
   - `countryRatingChangeWl.length === 2` (no override parameter)

INVALID (plan.md) has 15 values:
- strings: `"bbb+"`, `" BBB+"`, `"BBB+ "`, `"BBB−"`, `""`, `"CC"`, `"C"`, `"D"`, `"NR"`, `"WD"`, `"Baa1"`
- non-strings: `null`, `undefined`, `42`, `{}`

## Edge cases
- **The Ind. 12 thresholds:**

  | notches | WL |
  | --- | --- |
  | -1 | 0 |
  | 0 | 0 |
  | 1 | 1 |
  | 2 | 2 |
  | 3 | 2 |
  | 18 | 2 |

  Example pairs:
  - ("BB+","BBB-") → 0 (notches -1); ("A","A") → 0 (notches 0)
  - ("BBB","BBB-") → 1 (notches 1); ("BBB","BB+") → 2 (notches 2); ("BBB+","BB+") → 2 (notches 3)
  - ("AAA","CCC-") → 2 (notches 18)
- **Ends of the scale:**
  - ("AAA","AA+") → 1; ("CCC","CCC-") → 1
  - ("AAA","AAA") → 0; ("CCC-","CCC-") → 0
  - ("AA+","AAA") → 0; ("CCC-","AAA") → 0
- **Different from `notchCalculator` on purpose (X-calc-wl-rule):** ("BBB","BBB-") gives Ind. 12 = 1 but `notchCalculator(...).wl` = 0. ("BBB","BB+") gives Ind. 12 = 2 but `notchCalculator(...).wl` = 1. A result equal to `notchCalculator`'s wl on these pairs is a defect.
- **Return type:** the number primitive. Not a string, boolean or `-0`: `Object.is(countryRatingChangeWl("BB","BBB"), 0)`.
- **Missing or partial arguments:** `countryRatingChangeWl()` and `countryRatingChangeWl("BBB")` throw `RangeError`.
- **Inputs beyond INVALID** (plan Scope: every other input throws). Each throws `RangeError` in either position, because the error comes from `notchChange`:
  - `new String("BBB")`, `["BBB"]`
  - `"toString"`, `"__proto__"`
  - `0`, `NaN`, `true`, `10n`
  - `Symbol("BBB")`, `Object.create(null)`
- **No error handling:** no `try/catch` that returns 0 or another default, no coercion, trimming or case folding (NFR-security).
- **A third argument has no effect:** `countryRatingChangeWl("BBB","BBB-", 2)` → 1. The function computes only from its two arguments (PRD-scope; there is no override parameter).
- **The error message text is not part of the contract.** Tests check only the type: `assert.throws(fn, RangeError)`.
