# T-02: countryRating.mjs: countryRatingChangeWl (Ind. 12)

## User story
As a credit analyst filling in Ind. 12 (country rating change), I want the WL computed from the country's rating 12 months ago and its current rating, so that a 1-notch downgrade gives WL=1 and a downgrade of 2 or more gives WL=2 without me counting notches.

## Traces to
AC-1 (the `countryRatingChangeWl` export), AC-4 (for `countryRatingChangeWl`), AC-5, AC-8, AC-9 (for `src/indicators/countryRating.mjs`), AC-10 (JSDoc on `countryRatingChangeWl`).
Requirements: REQ-03-12, REQ-02-02, REQ-02-08, REQ-06-02. Decisions: CON-interface, CON-errors, X-direction, X-window, X-scales, X-modifiers, PRD-priority, TST-strategy, NFR-security.

## Acceptance criteria
1. (AC-1) Given `src/indicators/countryRating.mjs`, when a test does `import { countryRatingChangeWl } from "../../src/indicators/countryRating.mjs"`, then `typeof countryRatingChangeWl === "function"`.
2. (AC-5) Given a 1-notch downgrade between the rating 12 months prior and the current rating, when `countryRatingChangeWl(previous, current)` is called, then it returns the number `1`: `("AAA","AA+")` → `1`, `("BBB-","BB+")` → `1`.
3. (AC-5) Given a downgrade of 2 or more notches, when `countryRatingChangeWl` is called, then it returns `2`: `("BBB+","BBB-")` → `2`, `("BBB+","BB+")` → `2`, `("AAA","CCC-")` → `2`.
4. (AC-5) Given no change or an upgrade of any size, when `countryRatingChangeWl` is called, then it returns `0`, and `Object.is(result, 0)` holds: `("AAA","AAA")` → `0`, `("BBB-","BBB")` → `0`, `("BB+","BBB+")` → `0`, `("CCC-","AAA")` → `0`.
5. (AC-5, X-window) Given an intermediate path BBB → BB → BBB-, when the caller passes only the two end points `("BBB","BBB-")`, then the result is `1`. Only the net change counts.
6. (AC-5) Given any of the 361 valid ordered pairs, when `countryRatingChangeWl` is called, then `typeof result === "number"` and `[0,1,2].includes(result)`.
7. (AC-4) Given an argument that is not exactly one of the 19 `RATING_SCALE` strings, passed as `previous` or as `current`, when `countryRatingChangeWl` is called, then it throws an instance of `RangeError`. It never throws `TypeError` and never returns a value. This holds for every value in the "Invalid ratings" table, including `countryRatingChangeWl(null,"AAA")` and `countryRatingChangeWl("BBB+","Baa1")`.
8. (AC-4) Given a missing argument, when `countryRatingChangeWl("BBB")` or `countryRatingChangeWl()` is called, then it throws `RangeError`.
9. (AC-8) Given a list of the 19 ratings typed out in the QA test (not imported), when all 361 ordered pairs `(p,c)` are checked, then for each pair `notchChange(p,c) === indexOf(c) - indexOf(p)`, `notchCalculator(p,c).notches === notchChange(p,c)`, `notchCalculator(p,c).wl === countryRatingChangeWl(p,c)` and `notchCalculator(p,c,12).wl === countryRatingChangeWl(p,c)`. The typed list also deep-strict-equals the imported `RATING_SCALE`.
10. (AC-9) Given any valid pair, when `countryRatingChangeWl` is called, then the result is not a `Promise`, and repeated calls with the same arguments return strictly equal results. `RATING_SCALE` still deep-strict-equals the AC-1 list after the suite.
11. (AC-9, NFR-security) Given the source text of `src/indicators/countryRating.mjs`, when it is inspected, then its only `import` is from `"../ratings/notch.mjs"`. It has no `node:` module, no package, no dynamic `import(`, no `require(`, no `eval(` and no `new Function`. `package.json` has no `dependencies` key, and `src/ratings/notch.mjs` is unchanged by this card (`git diff` on the card branch touches no file under `src/ratings/`).
12. (AC-10) Given the source, when a reviewer reads it, then `countryRatingChangeWl` has a JSDoc block that has `@param` for `previous` (the rating 12 months prior) and `current`, `@returns` (`0 | 1 | 2`, with the mapping), and `@throws {RangeError}`.

## Edge cases
- WL thresholds: notches `-18` → 0, `-1` → 0, `0` → 0, `1` → 1, `2` → 2, `18` → 2.
- The IG/HY crossing `("BBB-","BB+")` is 1 notch → `1`. Crossing gets no extra weight.
- The validation is `notchChange`'s. The `RangeError` it throws must reach the caller unchanged: not caught, not wrapped, not turned into `0`. A `try/catch` that returns `0` would break AC-4 silently.
- Prototype-property names (`"__proto__"`, `"constructor"`, `"toString"`) and odd non-strings (`Symbol("BBB+")`, `Object.create(null)`, `new String("BBB+")`) throw `RangeError`, not `TypeError`.
- Outlook or watch text (`"BBB+ (negative)"`) is rejected, not stripped. Normalisation is the caller's job.
- Extra arguments beyond the second are not specified and are not tested.
