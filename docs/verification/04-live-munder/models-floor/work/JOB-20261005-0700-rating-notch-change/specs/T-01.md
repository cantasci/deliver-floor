
# T-01: Implement notchChange rating calculation function

## User story

As a developer building credit rating indicators for the Watchlist POC, I want a pure function that computes the notch (step) difference between two credit ratings, so that I can determine whether a rating has upgraded (improved), downgraded (worsened), or remained unchanged, using a signed integer convention.

## Traces to

- **REQ-06-02 (part):** "Given a previous and a current rating, the system computes the notch change between them"
- **Clarifications:** C1 (rating scale, trimming, case-insensitivity), C2 (error handling), C3 (sign convention)
- **Plan ACs:** AC-1 through AC-11

## Acceptance criteria

1. **AC-1 (REQ-06-02, C1):** `RATING_SCALE` constant is exported from `src/ratings/notch.mjs` as an array of exactly 19 credit rating strings in order from best (index 0) to worst (index 18): `['AAA', 'AA+', 'AA', 'AA-', 'A+', 'A', 'A-', 'BBB+', 'BBB', 'BBB-', 'BB+', 'BB', 'BB-', 'B+', 'B', 'B-', 'CCC+', 'CCC', 'CCC-']`. Each rating appears exactly once. The array is immutable (const, not reassignable).

2. **AC-2 (REQ-06-02, C2, C3):** Given two valid rating strings from `RATING_SCALE`, when `notchChange(previous, current)` is called, then the function returns an integer equal to `index(current) - index(previous)`. Example: `notchChange('BBB+', 'BB+')` returns `3` because BB+ is at index 10 and BBB+ is at index 7 (10 - 7 = 3).

3. **AC-3 (REQ-06-02, C3):** Given a downgrade (current rating is worse than previous, higher index in RATING_SCALE), when `notchChange(previous, current)` is called, then the result is a positive integer. Example: `notchChange('BBB+', 'BB+')` returns `+3` (BBB+ at index 7 to BB+ at index 10 is a 3-notch downgrade).

4. **AC-4 (REQ-06-02, C3):** Given an upgrade (current rating is better than previous, lower index in RATING_SCALE), when `notchChange(previous, current)` is called, then the result is a negative integer. Example: `notchChange('BB+', 'BBB+')` returns `-3` (BB+ at index 10 to BBB+ at index 7 is a 3-notch upgrade).

5. **AC-5 (REQ-06-02, C3):** Given that both parameters are the same rating, when `notchChange(previous, current)` is called, then the result is exactly `0`. Example: `notchChange('A', 'A')` returns `0`.

6. **AC-6 (REQ-06-02, C1):** Given input with leading and/or trailing whitespace (spaces, tabs, newlines, carriage returns), when `notchChange(previous, current)` is called, then the input is trimmed using `String.prototype.trim()` before processing. Example: `notchChange('  BBB+  ', 'BB+')` returns `3` (same as without whitespace).

7. **AC-7 (REQ-06-02, C1):** Given input with letters in different case (lowercase, uppercase, mixed), when `notchChange(previous, current)` is called, then the input is normalized to uppercase and compared case-insensitively. Example: `notchChange('bbb+', 'bb+')` returns `3` (same as `notchChange('BBB+', 'BB+')`); `notchChange('BbB+', 'Bb+')` returns `3`.

8. **AC-8 (REQ-06-02, C2):** Given a rating string that is not in `RATING_SCALE` (after `String.prototype.trim()` and case normalization to uppercase), when `notchChange(previous, current)` is called, then the function throws a `RangeError`. Example: `notchChange('XYZ', 'BBB+')` throws `RangeError`; `notchChange('BBB+', 'INVALID')` throws `RangeError`.

9. **AC-9 (REQ-06-02, C2):** Given an empty string (even if after trim it results in an empty string), when `notchChange(previous, current)` is called, then the function throws a `RangeError`. Example: `notchChange('', 'BBB+')` throws `RangeError`; `notchChange('   ', 'BBB+')` (after trim becomes empty) throws `RangeError`.

10. **AC-10 (REQ-06-02, C2):** Given a non-string primitive as either parameter (number, boolean, null, undefined, symbol), when `notchChange(previous, current)` is called, then the function throws a `RangeError`. Examples: `notchChange(123, 'BBB+')` throws `RangeError`; `notchChange(undefined, 'BBB+')` throws `RangeError`; `notchChange(null, 'A')` throws `RangeError`; `notchChange(true, 'A')` throws `RangeError`; `notchChange('A', Symbol('x'))` throws `RangeError`.

11. **AC-11 (REQ-06-02, C2):** Given a String object instance (created with `new String('X')`) as either parameter, when `notchChange(previous, current)` is called, then the function throws a `RangeError`. String objects are not primitive strings and must be rejected. Example: `notchChange(new String('A'), 'BBB+')` throws `RangeError`; `notchChange('A', new String('BBB+'))` throws `RangeError`.

## Edge cases

### Boundaries
- **AAA → CCC-:** Maximum downgrade (index 0 to index 18) returns `+18`. Example: `notchChange('AAA', 'CCC-')` returns `18`.
- **CCC- → AAA:** Maximum upgrade (index 18 to index 0) returns `-18`. Example: `notchChange('CCC-', 'AAA')` returns `-18`.
- **First to second:** `notchChange('AAA', 'AA+')` returns `1`.
- **Last to second-last:** `notchChange('CCC', 'CCC-')` returns `1`.

### Input validation (applies to BOTH arguments)
- Empty string in either argument (before or after trim) → RangeError.
- Non-string in either argument (number, boolean, null, undefined, symbol, String object) → RangeError.
- Unknown rating in either argument (not in RATING_SCALE after trim/normalize) → RangeError.

### Whitespace handling
- Leading whitespace: `notchChange('  AAA', 'A')` returns `5`.
- Trailing whitespace: `notchChange('AAA  ', 'A')` returns `5`.
- Both: `notchChange('  AAA  ', '  A  ')` returns `5`.
- Tab characters: `notchChange('\tAAA\t', 'A')` returns `5`.
- Newline: `notchChange('\nAAA\n', 'A')` returns `5`.
- Multiple spaces: `notchChange('   AAA   ', 'A')` returns `5`.

### Case handling
- All uppercase: `notchChange('AAA', 'A')` returns `5` (expected).
- All lowercase: `notchChange('aaa', 'a')` returns `5`.
- Mixed case: `notchChange('AaA', 'a')` returns `5`; `notchChange('BBb+', 'bb+')` returns `0`.
