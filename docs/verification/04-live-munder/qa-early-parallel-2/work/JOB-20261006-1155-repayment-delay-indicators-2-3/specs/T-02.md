# T-02: Indicator 3 — delays in 12 months (delayCount)

## User story
As a POC screen (built later), I want the exported option list for Indicator 3 and a function that maps the chosen option to its WL, so that the dropdown shows exactly the allowed values and the WL is computed consistently.

## Traces to
AC-6, AC-7, AC-8, AC-9, AC-10, AC-11, AC-12 of the plan. REQ-03-03. C1, C2, C4, C5, C6. Readiness: X-options-export, X-options-immutability, X-error-message, CON-errors.

## Acceptance criteria
Files: `src/indicators/delayCount.mjs` and `test/indicators/delayCount.test.mjs` (unit, dev). Public names: `export const DELAY_COUNT_OPTIONS` and `export function delayCountWl(option)`. "Throws RangeError" means `assert.throws(fn, RangeError)`.

1. **AC-6 (REQ-03-03, C1, C4):** Given the module, when `DELAY_COUNT_OPTIONS` is imported, then it deep-equals `["0", "1", ">1"]` in this order, and `Object.isFrozen(DELAY_COUNT_OPTIONS) === true`.
2. **AC-7 (REQ-03-03, C2):** Given each exact option, when `delayCountWl(option)` is called, then it returns: `"0"` → 0, `"1"` → 1, `">1"` → 2. Every entry of `DELAY_COUNT_OPTIONS` is accepted.
3. **AC-8 (REQ-03-03, C1, C5):** Given an option padded with leading and trailing whitespace of any kind, when `delayCountWl` is called, then the result equals that of the bare option. `" 0 "` → 0, `"\t1\n"` → 1, `" >1 "` → 2.
4. **AC-9 (REQ-03-03, C1, C5):** Given a string that is not an exact option after `trim()`, when `delayCountWl` is called, then it throws a `RangeError` whose message contains `JSON.stringify(input)`.
5. **AC-10 (REQ-03-03, C5):** Given a non-string input, when `delayCountWl` is called, then it throws a `RangeError` (no coercion) whose message contains `typeof input`. In particular the numbers `0`, `1` and `2` throw, even though the options look like numbers.
6. **AC-11 (REQ-03-03, C3, C4, CLAUDE.md), this module:** `delayCount.mjs` is plain ESM with no imports and no I/O, it adds no dependency to `package.json`, it does not import `daysWithDelay.mjs`, and `node --test test/indicators/delayCount.test.mjs` exits 0.
7. **AC-12 (REQ-03-03, C1), this module:** Given the same input called repeatedly, when `delayCountWl` is called, then it returns the same WL each time; after a call that throws, `DELAY_COUNT_OPTIONS` is unchanged.
8. **Error message (X-error-message, supports AC-9 and AC-10):** the message also names the indicator and lists the allowed options, e.g. `Indicator 3 (delays in 12 months): invalid option "2"; expected one of: "0", "1", ">1"`. Tests assert the type and that the rejected value (or the `typeof` word) is contained, never the full text.

## Edge cases
- The caller counts the delays (C6): a raw count such as `"2"`, `"3"`, `"10"` is not an option and throws; the caller must pick `">1"`.
- Number-like variants: `"00"`, `"01"`, `"1.0"`, `"-1"`, `"+1"`, `"1e0"` → RangeError.
- Inner whitespace is never changed: `"> 1"`, `">  1"` → RangeError. `" >1 "` is valid (trims to `">1"`).
- Near misses: `">=1"`, `">0"`, `"<1"`, `"one"` → RangeError.
- Empty and whitespace-only: `""`, `"   "`, `" "` → RangeError.
- Non-strings: `0`, `1`, `2`, `undefined`, `null`, `false`, `[]`, `["1"]`, `new String("1")` → RangeError, never coerced.
- Option strings that belong to Indicator 2 (`"no delay"`, `">3 days"`) → RangeError here.
