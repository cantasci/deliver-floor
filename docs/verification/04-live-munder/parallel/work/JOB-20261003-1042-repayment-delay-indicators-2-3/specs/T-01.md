# T-01 — REQ-03-02 Indicator 2 "Days with delay": `DAYS_WITH_DELAY_OPTIONS` + `daysWithDelayWl`

## User story
As a developer building the Watchlist POC screens (EPIC-03), I want a pure function that turns the Indicator 2 "Days with delay" dropdown option into a Watchlist level (WL), plus the ordered option list, so the screens can render the exact allowed labels and obtain the WL without re-implementing the rule.

## Edge cases
- Lookup-table trap: `"constructor"`, `"__proto__"`, `"toString"`, `"hasOwnProperty"` must throw, not return an inherited property — a plain `{…}` lookup fails this; use a `Map`, a null-prototype object with an own-property check, or `indexOf` on the options array.
- Message-building trap: naive `${option}` throws `TypeError` for `Symbol(...)` and `Object.create(null)`; `JSON.stringify(10n)` throws for BigInt. The function must still end in `RangeError`.
- Inner whitespace is not normalised: `">3  days"` → RangeError; `">3 days"` (NBSP inside) → RangeError.
- Characters outside `String.prototype.trim()` (e.g. zero-width space `"​>3 days"`) are not trimmed → RangeError (follows from X-trim-semantics).
- Wrapper/coercible objects are rejected: `new String(">3 days")` and an object whose `toString` returns a valid option → RangeError.
- Case is exact: `"No delay"` → RangeError.
- Empty after trimming: `""`, `"   "` → RangeError.
- Numeric-looking input: `"0"`, `"3"`, `0`, `3` → RangeError (Indicator 2 accepts only the label strings).
- The list cannot grow: after a failed `push`, `">120 days"` is still unknown → RangeError.
