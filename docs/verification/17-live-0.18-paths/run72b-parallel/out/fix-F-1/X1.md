# X1: Remove the never-ending test/zz-scale-loaded.test.mjs so `node --test` finishes

## User story
As the delivery team, I want the full `node --test` on the job branch to finish and pass, so that DEL-ci can be checked and the job can ship.

## Traces to
- Finding F-1 and DEL-ci. Protects the merged tests for AC-1 to AC-14 (T-01, T-02).
- **[P0]**: if this fails, the job branch can never pass DEL-ci and nothing ships.

## Acceptance criteria
1. Given the job branch with `test/zz-scale-loaded.test.mjs` present, when the dev commit is applied, then `test ! -e test/zz-scale-loaded.test.mjs` exits 0.
2. Given the dev commit, when `git diff --name-status <job branch>..<dev commit>` runs, then it prints exactly one line, `D	test/zz-scale-loaded.test.mjs`; nothing under `src/`, `test/indicators/` or `test/integration/` changes and no file is added.
3. Given the card branch, when `test ! -e test/zz-scale-loaded.test.mjs && timeout 60 node --test test/indicators/*.test.mjs` runs, then it exits 0 with `# fail 0` and `# cancelled 0`.
4. Given the dev commit, when its message is read, then it is one normal forward commit in the repo's commit format, with no history rewrite and no force push.
5. Given the stray file is absent, when `node --test test/integration/suiteFinishes/suiteFinishes.integration.test.mjs` runs, then it exits 0 within 5 s with 1 test passing, asserting `existsSync(<repo root>/test/zz-scale-loaded.test.mjs) === false` with the path built from `import.meta.url`.
6. Given the file is put back temporarily, when only the QA test file runs, then it fails with exit 1 and does not hang.
7. Given the QA test's source, when it is read, then it uses only `node:test`, `node:assert/strict`, `node:fs`, `node:path`, `node:url`, and never `child_process`, a nested `node --test`, `setInterval` or any open handle.
8. Given the card branch with the dev commit and the QA test, when `timeout 60 node --test` runs from the worktree root, then it exits 0 (not 124) with `# fail 0`, `# cancelled 0`, well under 60 s.

## Edge cases
- Exit 124 means some handle is still open: the card fails; if it is in another file, raise a new finding.
- Do not "repair" the stray file; delete it.
- The QA test must not depend on the current directory.

## Test design
| AC | Priority | Level | Scenarios |
|---|---|---|---|
| F-1 / DEL-ci | P0 | Dev: `verify` (1-4). QA: `test/integration/suiteFinishes/suiteFinishes.integration.test.mjs` + `qa_verify` `timeout 60 node --test` (5-8) | Main: file absent, suite exits 0. Boundary: finishes before 60 s. Error: with the stray file back the QA test fails, not hangs. Regression: T-01/T-02 tests still pass. |

QA's test: one terminating test asserting the stray file does not exist; then `qa_verify` proves the whole suite finishes.
