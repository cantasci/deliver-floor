# T-01: Rating scale, notchChange and notchCalculator (src/ratings/notch.mjs)

## User story
As a developer building other Watchlist POC parts, I want a pure, synchronous module that gives me the rating scale, the signed notch change between two ratings and the notch-calculator result `{ notches, direction, wl }`, so that I get the same answers everywhere (REQ-06-02).

## Acceptance criteria
Each criterion reads: Given the inputs listed, When the named function is called (or the module is imported/inspected), Then the stated result holds.
Files: `src/ratings/notch.mjs`, `test/ratings/notch.test.mjs`. `notchChange(p, c) = index(c) - index(p)`.

1. AC-1: `RATING_SCALE` deep-strict-equals the 19 ratings AAA, AA+, AA, AA-, A+, A, A-, BBB+, BBB, BBB-, BB+, BB, BB-, B+, B, B-, CCC+, CCC, CCC-; length 19; `Object.isFrozen` true; `push("CC")` throws TypeError and length stays 19.
2. AC-2: worse current gives positive: ("BBB+","BBB") → 1, ("BBB+","BBB-") → 2, ("BBB+","BB+") → 3, ("AAA","CCC-") → 18, ("CCC","CCC-") → 1.
3. AC-3: better current gives negative: ("BB+","BBB+") → -3, ("BBB","BBB+") → -1, ("CCC-","AAA") → -18.
4. AC-4: for each of the 19 ratings r, `notchChange(r, r)` is 0 and `Object.is(result, 0)` (never -0).
5. AC-5 (notch): `notchChange(" bbb+ ","BB+")` → 3; ("Bbb+","\tbb+\n") → 3; (" aaa ","AAA") → 0; (" aaa ","AAA") → 0; `notchCalculator("bbb+","bbb-")` → `{ notches: 2, direction: "downgrade", wl: 1 }`.
6. AC-6 (notch): each invalid value from list B, as `previous` (current "BBB") and as `current` (previous "BBB"), makes `notchChange` and `notchCalculator` throw `instanceof RangeError` — never TypeError, never a value. Message names the argument and quotes the value; tests check only the type.
7. AC-7: `notchCalculator` deep-strict-equals (no extra keys): ("BBB+","BB+") → `{notches:3,direction:"downgrade",wl:2}`; ("BBB+","BBB-") → `{2,"downgrade",1}`; ("AAA","CCC-") → `{18,"downgrade",2}`.
8. AC-8 (notch): `notchCalculator("BBB+","BBB")` → `{notches:1,direction:"downgrade",wl:0}` (Indicator 13 thresholds; intentionally differs from T-02).
9. AC-9: ("BB+","BBB+") → `{-3,"upgrade",0}`; ("BBB","BBB+") → `{-1,"upgrade",0}`; ("CCC-","AAA") → `{-18,"upgrade",0}`; ("A","A") → `{0,"unchanged",0}` with `Object.is(notches, 0)`.
10. AC-10: for all 361 ordered pairs: keys sorted are ["direction","notches","wl"]; notches === notchChange(p,c); direction downgrade/upgrade/unchanged by sign; wl 0 when notches<=1, 1 when ===2, 2 when >=3; wl in {0,1,2}; each call returns a new object.
11. AC-15 (notch): `Object.keys` of the module sorted is ["RATING_SCALE","notchCalculator","notchChange"]; no default export; results are not Promises.
12. AC-16 (notch): `node --test` exits 0; package.json has no dependencies/devDependencies; notch.mjs has no non-relative imports, no require, no fs/process/fetch, no console.

## Edge cases
- Non-strings must be rejected before `.trim()` (null.trim() would be a TypeError).
- Inner whitespace and look-alikes (U+2212, en dash, fullwidth letters) throw RangeError.
- Off-scale ratings (CC, C, RD, SD, D, NR, WD, Baa1, AAA+) throw; empty/whitespace-only throw; missing arguments throw RangeError.
- Boundaries ±18; wl thresholds at 1→0, 2→1, 3→2; every negative → 0.
- `-0`: use plain subtraction; no negation or Math.sign.
- Scale immutable; no module state.

## Test data
A. Valid pairs: see the acceptance criteria above, plus ("CCC","CCC-") → {1,"downgrade",0}.
B. Invalid values (each argument position, both functions): `""`, `"   "`, `"BB B"`, `"Baa1"`, `"BBB−"`, `"AAA+"`, `"CC"`, `"C"`, `"D"`, `"SD"`, `"NR"`, `null`, `undefined`, `7`, `{}`, `["BBB"]`.
Forbidden test data (C2): never use "BBB+ → BB+ = 2 notches, WL = 1" as an expected value.
