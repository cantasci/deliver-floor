# T-03 (re-run of T-01): Notch calculator: RATING_SCALE, notchChange, notchCalculator (src/ratings/notch.mjs)

## User story
As a developer of another Watchlist POC module, I want one shared helper that turns a previous and a current rating into a notch change, a direction and a WL, so that every screen and indicator counts notches the same way.

## Edge cases
- Scale ends AAA/CCC- valid in both positions; (AAA,AAA) and (CCC-,CCC-) → 0 / "unchanged" / wl 0.
- WL boundaries: 1 → wl 0, 2 → wl 1, 3 → wl 2; every negative value → wl 0 (a Math.abs bug would be caught by AC-5).
- ("BBB-","BB+") is 1 notch, downgrade, wl 0.
- Arrays/boxed strings: `["BBB"]` and `new String("BBB")` must throw RangeError (check `typeof x === "string"`).
- Non-strings (numbers, booleans, {}, null, undefined) and a missing argument (`notchChange("BBB")` reports `current`) throw RangeError, not TypeError from `.trim()`.
- Building the error message must never throw: `Symbol("x")` and `Object.create(null)` inputs must still end in RangeError.
- Both invalid → error names `previous`.
- " BBB " is valid (trim strips NBSP); "BBB +", "B BB", U+2212 minus and en dash "BBB–" are invalid.
- Mutating a returned object (`r.wl = 9`) must not affect later calls.
