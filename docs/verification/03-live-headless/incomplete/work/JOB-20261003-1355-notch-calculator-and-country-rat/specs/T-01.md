# T-01: Notch calculator helper: RATING_SCALE, notchChange, notchCalculator (src/ratings/notch.mjs) with unit tests

## User story
As a credit analyst (through the POC parts that import this module), I want to give a previous and a current rating and get back the signed notch change, the direction and the resulting WL, so that I can see how far a rating moved and what Watchlist level that movement causes under the Indicator 13 thresholds.

## Edge cases
- **Non-strings** (`null`, `undefined`, `42`, `{}`) throw `RangeError`, never `TypeError`. The type check must run before any `.trim()` or `.toUpperCase()`. By the same rule (C1 "anything else"), `new String("BBB")`, `[]` and `true` are also rejected. They are not asserted.
- **Whitespace only** (`""`, `"   "`) throws `RangeError`. Leading and trailing whitespace including `\t` and `\n` is removed. Inner whitespace (`"BBB +"`) is not, so it throws `RangeError`.
- **Off the scale but plausible** (`"CC"`, `"C"`, `"D"`, `"SD"`, `"NR"`, `"WD"`, `"AAA+"`, Moody's `"Baa1"`) throws `RangeError`. A real downgrade into default is therefore an error, not WL 2.
- **Both arguments invalid** throws `RangeError`. Which argument the message names first is not asserted.
- **Message** (reviewer check only, X-error-message): names the argument (`previous`/`current`) and the offending value, and lists the valid ratings. Tests assert the type only.
- **Extremes**: `("AAA","CCC-")` → `18`; `("CCC-","AAA")` → `-18`. No result falls outside `[-18, 18]`.
- **Zero**: unchanged must be `+0`, never `-0`, in both `notchChange` and `notchCalculator().notches`.
- **Returned object**: each call returns a new plain object.
- **The POC's "BBB+ → BB+ = 2 notches → WL=1" example is wrong** (C2). The correct result is 3 notches, WL 2. It must not appear in any test as an expected value.
