# T-02: Indicator 12 country rating change WL: countryRatingChangeWl (src/indicators/countryRating.mjs) with unit tests

## User story
As a credit analyst (through the POC parts that import this module), I want the Indicator 12 Watchlist level worked out from the previous and current country rating, so that a country downgrade raises the client's WL by the REQ-03-12 rule (1 notch → 1, 2 or more → 2, otherwise 0).

## Edge cases
- **Threshold boundaries for Ind. 12**: `n = 1` → `1`. `n = 2` → `2`. `n = 18` → `2` (capped). `n = 0`, `-1` or `-18` → `0`. The result is always one of `0`, `1` or `2`.
- **Deliberate difference from the calculator** (C6): a 1-notch downgrade gives Ind. 12 `1` but calculator `wl` `0`. A 2-notch downgrade gives `2` versus `1`. Do not reuse or harmonise `notchCalculator`'s thresholds.
- **Invalid input**: every value that `notchChange` rejects is rejected here with the same `RangeError`, including non-strings, whitespace-only and inner-space strings, and off-scale ratings such as `"CC"` and `"D"`.
- **Both arguments invalid**: throws `RangeError`. Which argument the message names is not asserted.
- **Full suite**: `node --test` from the root also picks up any QA files under `test/integration/**`. AC-14 means the whole suite exits `0`.
- **Defect found in `notch.mjs`**: report it. Do not edit `src/ratings/notch.mjs` or `test/ratings/notch.test.mjs` in this card.
