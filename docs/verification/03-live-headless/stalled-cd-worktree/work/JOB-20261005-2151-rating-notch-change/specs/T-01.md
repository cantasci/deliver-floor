# T-01: Add src/ratings/notch.mjs (RATING_SCALE + notchChange) with unit tests

## User story
As a developer of Indicators 11–13 and of the REQ-06-02 notch calculator, I want a pure, synchronous `notchChange(previous, current)` and a frozen `RATING_SCALE` that I can import from `src/ratings/notch.mjs`, so that I get the signed number of notches between two credit ratings (downgrade positive, upgrade negative, no change 0) without writing my own scale lookup.

## Traces to
AC-1 to AC-18 of plan.md. Requirements: REQ-06-02, C1, C2, C3, C4, Contract. Readiness: CON-interface, CON-errors, X-scale-bounds, X-module-shape, X-error-message, ARC-async, ARC-stack, DEL-docs, TST-strategy, PRD-conflicts.

Clarifications this spec relies on (none of them changes scope):
- **Imports (AC-16).** The plan says the module "imports no `node:` I/O module". The card is stricter: the module imports nothing. This spec uses the stricter rule, which also satisfies AC-16.
- **Error message (AC-15).** X-error-message fixes only the error type. The integration test may assert that the message is a non-empty string containing `previous` or `current`. Neither unit tests nor integration tests may assert the exact message text.
- **Invisible characters (AC-9, AC-10, AC-11, AC-12).** The plan shows them as literal characters. Here they are written as escapes: ` ` NBSP, `﻿` BOM, `​` zero-width space, `−` minus sign, `‐` hyphen. Test sources must use the escapes.
- **"npm test exits 0" (AC-17).** QA checks this on the command line. The integration test must not run `npm test` or a bare `node --test`, because it would start itself again in a loop.

## Edge cases
- **Signed zero.** The result for any equal pair, including the 19 diagonal pairs of AC-7, must be `+0`. `assert.strictEqual` (node:assert/strict) uses `Object.is`, so a `-0` from `-(prev - cur)` fails AC-3 and AC-7.
- **Loose string checks.** `['A']` and `new String('A')` both turn into `'A'` with `String()`. Both must still throw `RangeError` (AC-13). Only `typeof arg === 'string'` counts as a string.
- **Error type for non-strings.** Every invalid input throws `RangeError`, never `TypeError`. This includes `Symbol`, `BigInt`, functions and a missing argument (C2, PRD-conflicts).
- **Building the message.** A template literal or `+` with a Symbol throws `TypeError`. `String(Object.create(null))` and `String({toString(){throw …}})` throw too. In every one of these cases the error that reaches the caller must still be a `RangeError` (AC-15).
- **Trim rules (exactly `String.prototype.trim()`).** NBSP ` ` and BOM `﻿` at the ends are removed (AC-9). The zero-width space `​` is not removed, so the input is rejected (AC-10). After trimming, a whitespace-only string is empty and is rejected (AC-12).
- **Exact match only.** Prefix, suffix and substring matches are rejected: `'AAA+'`, `'BBB+u'`, `'BBB+ (neg)'`, `'A++'`. A lower-case valid rating such as `'b'` is valid (`notchChange('b','B') === 0`). It is not an invalid case.
- **Look-alike dashes.** U+2212 and U+2010 are not turned into `-`, so those inputs are rejected (AC-11).
- **Scale ends.** `('AAA','CCC-') === 18` and `('CCC-','AAA') === -18` are the extreme results. No result is outside -18..+18.
- **Extra arguments are ignored** (plan assumption). `notchChange('A','A','x') === 0`. Unit tests may check this. It is not an AC.
- **The shared scale stays intact.** Mutation attempts in one test (AC-5) must leave the module's `RATING_SCALE` unchanged for every later test in the same process. The module itself never sorts, reverses or otherwise mutates it.
- **Node 18.** The code must not use APIs newer than Node 18, such as `toSorted`, `toReversed`, `Object.groupBy`, Set methods or `isWellFormed`. The local runtime is v22.22.0, so the reviewer checks this by reading the code. QA cannot run Node 18 here.
- **Test discovery.** Both test files end in `.test.mjs` under `test/ratings/`, so bare `node --test` (`npm test`) finds them. QA confirms the reported test count is above 0.
