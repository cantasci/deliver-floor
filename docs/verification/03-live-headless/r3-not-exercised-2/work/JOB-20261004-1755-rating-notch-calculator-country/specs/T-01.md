# T-01: Rating scale, notchChange and notchCalculator in src/ratings/notch.mjs

## User story
As a developer of another POC part, I want one pure module that holds the 19-step rating scale and turns a previous and a current rating into a signed notch change, a direction and a WL, so that every part counts notches the same way and uses the corrected thresholds from C2.

## Traces to
AC-1..AC-9, AC-15 (the `notch.mjs` part, plus the `package.json` check). Requirements: REQ-06-02, REQ-03-13 (thresholds only), C1, C2, C3, C5, C6, C7, C8.

## What to build
- `src/ratings/notch.mjs` with named exports `RATING_SCALE`, `notchChange(previous, current)`, `notchCalculator(previous, current)`.
- `test/ratings/notch.test.mjs` with dev unit tests (`node:test` + `node:assert/strict`); each test name starts with its AC id, e.g. `AC-2: …`.
- Shared validation: (1) `typeof value === 'string'` first, else throw `RangeError` before `.trim()`; (2) `trim()`, then exact case-insensitive match against `RATING_SCALE`; (3) no match -> `RangeError`, for string input the message contains the raw value as passed; (4) validate both arguments before computing. An internal normaliser may be exported but is not part of the contract.

## Acceptance criteria
1. AC-1: Given `import { RATING_SCALE } from './src/ratings/notch.mjs'`, when inspected, then it deep-strict-equals ['AAA','AA+','AA','AA-','A+','A','A-','BBB+','BBB','BBB-','BB+','BB','BB-','B+','B','B-','CCC+','CCC','CCC-'], length 19, [0]==='AAA', [18]==='CCC-', and `Object.isFrozen(RATING_SCALE) === true`.
2. AC-1: Given the frozen `RATING_SCALE` in strict ESM, when `RATING_SCALE.push('D')` or `RATING_SCALE[0] = 'X'` runs, then each throws `TypeError` and the array still deep-equals the 19-entry list.
3. AC-2: Given two valid uppercase ratings, `notchChange(previous, current)` returns the integer `index(current) - index(previous)`: ('BBB+','BB+')→3; ('BBB+','BBB-')→2; ('BBB+','BBB')→1; ('AAA','AA+')→1; ('CCC','CCC-')→1; ('BB+','BBB+')→-3; ('A-','A')→-1; ('AAA','CCC-')→18; ('CCC-','AAA')→-18; ('A','A')→0; `Number.isInteger(result)` each.
4. AC-3: Given inputs differing only in case or leading/trailing whitespace, `notchChange`: ('bbb+','bb+')→3; ('  BBB+ ','\tbB+\n')→3; ('aaa','AAA')→0; (' a- ',' A ')→-1; ('ccc-','aaa')→-18.
5. AC-4: Given each invalid value v in ['', '   ', 'D', 'NR', 'CC', 'C', 'AAA-', 'AAA+', 'CCC--', 'BBB++', 'Baa1', 'BBB +', 'B B B', null, undefined, 3, {}], `notchChange(v,'A')` and `notchChange('A',v)` both throw `RangeError` (never `TypeError`, never a return value).
6. AC-4: Given ('NR','A'), ('A','NR'), ('A',undefined) and no arguments, `notchChange` throws `RangeError`.
7. AC-4: Given an invalid string such as 'NR', 'Baa1' or 'BBB +' in either position, `err.message` includes the raw value as passed (/NR/, /Baa1/, /BBB \+/); for '' and '   ' only the `RangeError` type is checked.
8. AC-5: Given a downgrade of 2+ notches, `notchCalculator` deep-strict-equals: ('BBB+','BB+')→{notches:3, direction:'downgrade', wl:2}; ('BBB+','BBB-')→{notches:2, direction:'downgrade', wl:1}; ('A','BBB+')→{notches:3, direction:'downgrade', wl:2}; ('AAA','CCC-')→{notches:18, direction:'downgrade', wl:2}; result is a plain object (prototype Object.prototype).
9. AC-6: Given a 1-notch downgrade, ('BBB+','BBB')→{notches:1, direction:'downgrade', wl:0} and ('CCC','CCC-')→{notches:1, direction:'downgrade', wl:0}.
10. AC-7: Given an upgrade or no change: ('BB+','BBB+')→{notches:-3, direction:'upgrade', wl:0}; ('A-','A')→{notches:-1, direction:'upgrade', wl:0}; ('CCC-','AAA')→{notches:-18, direction:'upgrade', wl:0}; ('A','A')→{notches:0, direction:'unchanged', wl:0}; (' a ','A')→{notches:0, direction:'unchanged', wl:0}.
11. AC-8: Given every ordered pair (p,c) of `RATING_SCALE` (361 pairs), `notchCalculator(p,c)` has notches === notchChange(p,c); direction 'downgrade' if >0, 'upgrade' if <0, 'unchanged' if 0; wl 2 if notches>=3, 1 if ===2, else 0; `Object.keys(r).sort()` equals ['direction','notches','wl'].
12. AC-9: Given AC-3-style input, `notchCalculator('bbb+',' BB+ ')` returns {notches:3, direction:'downgrade', wl:2}.
13. AC-9: Given every AC-4 invalid value in either position, plus no arguments, `notchCalculator` throws `RangeError` and returns no object.
14. AC-15: `notchChange.length === 2` and `notchCalculator.length === 2`; `notchChange('BBB+','BB+')` twice gives 3; `notchCalculator('BBB+','BB+')` twice gives deep-equal objects that are different references.
15. AC-15: `grep -nE "console\.|process\.|from 'node:|require\(" src/ratings/notch.mjs` prints nothing; `package.json` has no `dependencies`/`devDependencies` key.

## Edge cases
- Non-string input (`null`, `undefined`, `3`, `{}`, `[]`, missing argument) must give `RangeError`, not `TypeError` from `.trim()`; building the message must not throw a second error (message content for non-strings is not tested).
- Only leading/trailing whitespace goes (`String.prototype.trim()`); internal whitespace is never removed.
- Near-misses are rejected, not mapped: 'AAA+', 'AAA-', 'CCC--', 'BBB++', Moody's 'Baa1', 'D', 'SD', 'NR', 'WD', 'CC', 'C'. No alias table.
- Both arguments validated before computing: ('A', undefined) throws.
- Boundaries: ±18 extremes; 1-step edges at both ends; WL steps 0→1 at 2 notches and 1→2 at 3 notches.
- The POC line "BBB+ → BB+ = 2 notch, WL=1" is wrong; C2 corrects it to 3 notches, WL 2.
- `RATING_SCALE` is the frozen array itself.
