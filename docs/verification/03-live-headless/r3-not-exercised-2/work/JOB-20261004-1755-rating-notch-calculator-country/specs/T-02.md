# T-02: Indicator 12 countryRatingChangeWl in src/indicators/countryRating.mjs

## User story
As a credit analyst using the Watchlist POC, I want a country's rating change between the previous and the current review turned into Indicator 12's WL (0, 1 or 2), so that a sovereign downgrade raises the client's watchlist level by the rule in REQ-03-12.

## Traces to
AC-10..AC-14, AC-15 (the `countryRating.mjs` part), AC-16 (job level). Requirements: REQ-03-12, C1, C2, C3, C6, C7, C8.

## What to build
- `src/indicators/countryRating.mjs` with one named export `countryRatingChangeWl(previous, current)`: `import { notchChange } from '../ratings/notch.mjs'`; `n = notchChange(previous, current)`; return 2 if `n >= 2`, 1 if `n === 1`, else 0.
- No own validation, no try/catch, no copy of the scale. `notchChange`'s `RangeError` propagates unchanged.
- Do not modify `src/ratings/notch.mjs`; report defects instead.
- `test/indicators/countryRating.test.mjs` with dev unit tests named after their AC (e.g. `AC-10: …`).

## Acceptance criteria
1. AC-10: Given a downgrade, when `countryRatingChangeWl` is called, then: ('A','A-')→1, ('CCC','CCC-')→1, ('A','BBB+')→2, ('A','BBB')→2, ('BBB+','BB+')→2, ('AAA','CCC-')→2; every return value is one of 0, 1, 2.
2. AC-11: Given an upgrade or no change, when `countryRatingChangeWl` is called, then ('A-','A'), ('BB+','BBB+'), ('CCC-','AAA'), ('A','A') and ('bbb',' BBB ') each return 0.
3. AC-12: Given the same pair passed to both functions, when `countryRatingChangeWl(p,c)` is compared with `notchCalculator(p,c).wl`, then: ('BBB+','BBB')→1 vs 0; ('BBB+','BBB-')→2 vs 1; ('BBB+','BB+')→2 vs 2; ('BB+','BBB+')→0 vs 0 (the difference is intended, C6).
4. AC-13: Given every ordered pair (p,c) of `RATING_SCALE` (361 pairs), when `countryRatingChangeWl(p,c)` is called, then it equals 2 if `notchChange(p,c) >= 2`, 1 if `=== 1`, else 0.
5. AC-13: Given `src/indicators/countryRating.mjs` read as text (in the test only, via `node:fs`), when inspected, then it matches /import\s*\{[^}]*\bnotchChange\b[^}]*\}\s*from\s*['"]\.\.\/ratings\/notch\.mjs['"]/ and contains neither `AAA` nor `CCC-` anywhere, comments included.

## Edge cases
- Invalid input is not handled here: do not catch, re-wrap or pre-check; the `RangeError` is whatever `notchChange` throws.
- Non-strings must give `RangeError` (guaranteed by T-01); the AC-14 tests confirm it.
- Boundaries: ('AAA','AA+')→1 is the smallest downgrade; ('BBB+','BBB-')→2; 18 notches still gives 2; negative or zero gives 0.
- Whitespace/case: (' a ','a-')→1; ('bbb',' BBB ')→0; internal spaces throw.
- The AC-13 source check covers comments: do not write `AAA` or `CCC-` in comments or JSDoc in this file.
- AC-16: run in the job-branch worktree, not the main checkout; helpers under `test/` must be named `*.test.mjs` or be side-effect free.
