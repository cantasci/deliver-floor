# T-02: Indicator 12 countryRatingChangeWl in src/indicators/countryRating.mjs, built on notchChange (with unit tests and JSDoc)

## User story
As a credit analyst, I want the country rating change (Indicator 12) scored as WL 0, 1 or 2 from the previous and current country rating I confirmed, so that a country downgrade raises the client's watchlist level by the REQ-03-12 rule.

## What to build
- **Prerequisite:** T-01 is merged into the job branch. Do not modify `src/ratings/**` or `test/ratings/**`.
- **`src/indicators/countryRating.mjs`.** Its only import is `import { notchChange } from '../ratings/notch.mjs'`. It has one export:
  - **`countryRatingChangeWl(previous, current)`** sets `d = notchChange(previous, current)` and returns `0` if `d <= 0`, `1` if `d === 1`, `2` if `d >= 2`.
  - It is synchronous.
  - It has no rating list, trimming, case folding, validation, `try`/`catch` or re-wrapping of its own. Errors from `notchChange` pass straight through (AC-13).
- **JSDoc** goes above the export.
- **`test/indicators/countryRating.test.mjs`** uses `node:test` and `node:assert/strict`.

## Edge cases
- **Boundaries of d.** −18, −1 and 0 → `0`. 1 → `1`. 2, 3 and 18 → `2`.
- **Upgrade results are `+0`**, never `-0`. `strictEqual` catches `-0`.
- **The return value is the number itself**, never `'1'`, `true` or `NaN`.
- **Invalid input** gets the same `RangeError` that `notchChange` throws, passed through unchanged. Its message still names `previous`/`current` (reviewer check). Both arguments invalid: `RangeError`. Non-strings and string wrappers, such as `['BBB']` and `new String('BBB')`: `RangeError`, inherited from T-01.
- **Normalisation is inherited.** `(' bbb+ ','Bb+')` → `2` and `('\tA\n','a-')` → `1`.
- **The 1-notch difference from `notchCalculator` (C6) is intended.** It must not be "fixed" in either module.
- **No dependence on `notchCalculator`.** The module does not import or call it.
