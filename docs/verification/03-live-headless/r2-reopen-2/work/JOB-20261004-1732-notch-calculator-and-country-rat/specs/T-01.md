# T-01: Rating scale, notchChange and notchCalculator in src/ratings/notch.mjs (with unit tests and JSDoc)

## User story
As a credit analyst, using the POC screens that call this library, I want to enter a previous and a current rating and get back the signed notch change, the direction and the resulting WL, so that every part of the Watchlist tool scores a rating move the same way.

## What to build
- **`src/ratings/notch.mjs`.** It has no `import` statements and three named exports:
  - **`RATING_SCALE`**: the 19 C1 ratings, best first, frozen with `Object.freeze` (X-scale-shape).
  - **`notchChange(previous, current)`**: returns a number equal to position(current) − position(previous).
    - Positive means a downgrade, negative an upgrade, and 0 means unchanged. It never returns `-0`.
  - **`notchCalculator(previous, current)`**: returns a new plain object with exactly three keys.
    - `notches`: equal to `notchChange(previous, current)`, signed the same way (CON-interface).
    - `direction`: `'downgrade'` / `'upgrade'` / `'unchanged'`.
    - `wl`: uses the Indicator 13 thresholds. It is 0 if `notches <= 1`, 1 if `=== 2`, and 2 if `>= 3` (C2, C3, C6).
- **One internal helper, not exported**, turns an argument into a scale position. Both functions use it.
  - If `typeof value !== 'string'`, it throws `RangeError`.
  - Otherwise it calls `String.prototype.trim()` and matches the result against the scale, ignoring case.
  - If there is no match, it throws `RangeError`. The message names the argument (`previous` / `current`) and the bad value (X-error-message).
  - There is no fallback and no partial result.
- **JSDoc** goes directly above each of the three exports (DEL-docs).
- **`test/ratings/notch.test.mjs`** uses `node:test` and `node:assert/strict`.
- **Do not touch** `package.json`, `README.md`, `src/indicators/**` or `test/indicators/**`.

## Edge cases
- **Strings only, no type conversion.** These must all throw `RangeError`: `['BBB']` (`String(['BBB'])` is `'BBB'`, so a coercing implementation would wrongly accept it), `new String('BBB')`, `{ toString(){ return 'BBB'; } }`.
- **Trimming follows `String.prototype.trim` (X-input-trim).**
  - Valid: `' BBB '`, `'　BBB'`, `'\r\nBBB\t'`.
  - Invalid (`RangeError`): `'​BBB'` (zero-width space is not removed by trim).
  - Whitespace inside the value is kept, so `'B B B+'` and `'BBB +'` throw `RangeError`.
  - Whitespace-only input trims to `''` and throws `RangeError`.
- **Lookup guards.** `'constructor'`, `'__proto__'`, `'toString'`, `'length'`, `'0'` and `'7'` must each throw `RangeError` (protects against object-map lookups or array-index use of the input).
- **Both arguments invalid** (`notchChange('X','Y')`): throws `RangeError`. Which argument the message names is not asserted.
- **Boundaries.** Ends of the scale: ±18 between `AAA` and `CCC-`. Adjacent ratings at the ends: `('AA+','AAA')` → −1 and `('CCC','CCC-')` → 1. WL steps: notches 1 → 0, 2 → 1, 3 → 2, 18 → 2, any negative → 0.
- **Zero.** `notches` is `+0` for unchanged ratings. `assert.strictEqual` and `deepStrictEqual` use Object.is, so they catch `-0`.
- **No side effects.** Calls do not change `RATING_SCALE` or the arguments. The same call twice gives deep-equal, separate objects.
- **Error message** names `previous`/`current` and the bad value. The reviewer checks this; the tests do not assert it.
