# T-01: Rating scale, notchChange and notchCalculator (REQ-06-02)

## User story
As a credit analyst (through the POC modules that import this library), I want to give a previous and a current rating and get back the signed notch change, the direction and the resulting WL, so that a rating move is turned into a Watchlist level the same way every time.

## Edge cases
- **Scale ends.** `AAA → AAA` and `CCC- → CCC-` give `0`/`"unchanged"`/`0`. `AAA → CCC-` gives `18`, WL 2. `CCC- → AAA` gives `-18`, WL 0.
- **WL thresholds.** Downgrades of 1, 2 and 3 notches give WL 0, 1 and 2: `BBB+→BBB`, `BBB+→BBB-`, `BBB+→BB+`. 4 or more notches still give WL 2 (`BBB+→BB`, `AAA→CCC-`). Upgrades of any size give WL 0 (`BBB→BBB+`, `BB+→BBB+`, `CCC-→AAA`).
- **Neighbours that share a prefix.** `"B"`, `"BB"` and `"BBB"` are three different ratings (indices 14, 11, 8). Matching must be exact, not by prefix: `notchChange("BBB","B") === 6`.
- **What `trim()` does not remove.** U+200B (zero-width space) is not whitespace for `trim()`, so `"​BBB"` is rejected with `RangeError`. This follows from the X-input-whitespace definition.
- **Internal whitespace** is never removed: `"BBB +"`, `"B BB+"` and `"BB B"` throw `RangeError`.
- **Non-strings.** The `typeof x === "string"` check comes before `trim()`. So `null`, `undefined`, a missing argument, `7`, `{}`, `["BBB"]` and `new String("BBB")` throw `RangeError`, never `TypeError` from calling `.trim` on a non-string.
- **Case folding** uses `toUpperCase()`, not `toLocaleUpperCase()`. The result must not depend on the process locale.
- **Unchanged is `+0`.** `Object.is(notchChange("CCC-","CCC-"), 0)` is true, and `notchCalculator("A","A").notches` is `+0` too.
- **Freezing.** Only `RATING_SCALE` is frozen. The object `notchCalculator` returns is not.
