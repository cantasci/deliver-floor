# T-02: Indicator 12 country rating change WL (REQ-03-12)

## User story
As a credit analyst (through the POC modules that import this library), I want the Indicator 12 WL to be worked out automatically from the previous and current country rating, so that a country downgrade raises the client's Watchlist level the same way every time.

## Traces to
AC-3 (indicator part), AC-4 (indicator part), AC-7, AC-8, AC-9 (indicator part), AC-10, AC-11 (indicator part), AC-12. Requirement and clarification ids: REQ-03-12, REQ-06-02 (AC-8 only), C1, C3, C4, C6, C7, C8, CON-errors, X-input-whitespace, X-error-message, X-wl-range, X-indicator13-scope.

## Acceptance criteria
Module `src/indicators/countryRating.mjs`. Tests go in `test/indicators/countryRating.test.mjs` and use `node:test` and `node:assert/strict`. This card depends on T-01's `src/ratings/notch.mjs`, which must not be modified.

1. **AC-7 (REQ-03-12, C3).** Given two valid ratings, when `countryRatingChangeWl(previous, current)` is called, then it returns a number in {0, 1, 2}:
   - `("BBB+","BBB") → 1`, `("BBB+","BBB-") → 2`, `("BBB+","BB+") → 2`, `("AAA","CCC-") → 2`
   - `("BBB","BBB+") → 0`, `("CCC-","AAA") → 0`, `("A","A") → 0`
2. **AC-7 / AC-10, all pairs.** Given every one of the 361 pairs `(p, c)` from `RATING_SCALE × RATING_SCALE` (both imported from `../../src/ratings/notch.mjs`), when `countryRatingChangeWl(p, c)` is called, then with `n = notchChange(p, c)` it returns `2` if `n >= 2`, `1` if `n === 1`, and `0` otherwise. Every result satisfies `Number.isInteger` and lies in [0, 2].
3. **AC-3, indicator part (C1, X-input-whitespace).** `countryRatingChangeWl(" bbb+","BBB\n") === 1`. Also `countryRatingChangeWl(" bbb+","﻿bb+") === 2`.
4. **AC-4, indicator part (C1, CON-errors, X-error-message).** Given one argument is `"BBB"` and the other is any value in table B of T-01, when `countryRatingChangeWl` is called with the invalid value as `previous`, and again as `current`, then `assert.throws(fn, RangeError)` passes. The error is thrown synchronously and is never caught, wrapped, turned into a fallback value or retyped. `countryRatingChangeWl("XYZ","QQQ")` throws `RangeError`. Tests assert only the type.
5. **AC-8 (REQ-03-12, REQ-06-02, C6).** Given `("BBB+","BBB")`, when both functions are called in the same test, then `notchCalculator("BBB+","BBB").wl === 0` and `countryRatingChangeWl("BBB+","BBB") === 1`. The test name states that the difference is intended (C6).
6. **AC-9, indicator part (C7).** `countryRatingChangeWl.length === 2`. Calling `("BBB+","BBB")`, then `("BBB+","BB+")`, then `("BBB+","BBB")` gives `1`, `2`, `1`. No third parameter, no override and no stored state.
7. **AC-10 (REQ-03-12 "auto-calculated", Contract "built on notchChange").** Given the text of `src/indicators/countryRating.mjs`, then:
   - it has exactly one static import: `notchChange` from `"../ratings/notch.mjs"`
   - it has no quoted string literal `"BBB+"`, `'BBB+'`, `"CCC-"` or `'CCC-'`, so there is no copy of the rating list
   - its results match `notchChange` for all 361 pairs (criterion 2).
8. **AC-11, indicator part (C8, CLAUDE.md, X-indicator13-scope).**
   - Exports: `import * as m from "../../src/indicators/countryRating.mjs"` has `countryRatingChangeWl`. It has no `externalRatingChangeWl` and no `default`.
   - Source: the text contains no `externalRatingChangeWl`, no `node:`, `fs`, `http` or `require(` import, no `import(`, no `console.` and no `process.`.
   - Synchronous: `typeof countryRatingChangeWl("A","A") === "number"`, not a Promise.
   - `package.json` is unchanged (no `dependencies` or `devDependencies`).
9. **AC-12 (TST-strategy, DEL-ci).** Given the repository root, when `node --test` (= `npm test`) runs, then it exits 0 and its output includes the tests from both `test/ratings/notch.test.mjs` and `test/indicators/countryRating.test.mjs`. Together they cover AC-1 to AC-9. The tests may use `node:fs` to read source text; `src/` may not.

## Edge cases
- **Threshold boundaries.**

  | Notch change | WL |
  |---|---|
  | +1 | 1 |
  | +2 | 2 |
  | +3 and beyond (`BBB+→BB+`, `AAA→CCC-`) | 2 |
  | 0 | 0 |
  | -1 | 0 |
  | -18 | 0 |

  WL 3 and WL 4 are never returned (X-wl-range).
- **Scale ends.** `("CCC-","CCC-") → 0`, `("AAA","AAA") → 0`, `("CCC+","CCC-") → 2`, `("CCC","CCC-") → 1`.
- **Invalid input.** Validation comes only from `notchChange`, with `previous` checked first. A non-string such as `null` or `new String("BBB")` throws `RangeError`, not `TypeError`. A blank string `"   "` or `" "` throws `RangeError`.
- **Same input, different module (C6).** A 1-notch downgrade gives 1 here and wl 0 from `notchCalculator`. This is not a defect and must not be "harmonised".
- **Defects in `notch.mjs`.** If T-01's module behaves differently from its spec, report the defect. Do not patch it or work around it inside `countryRating.mjs`.
- **Comments in the source.** Comments may describe ratings without quoted literals. The source check only looks for the quoted forms listed in criterion 7.
