# T-01: ratings: add RATING_SCALE and notchChange(previous, current) in src/ratings/notch.mjs, with unit tests

## User story
As a developer building Watchlist indicators 11–13 and the REQ-06-02 notch calculator, I want one pure function that gives the signed number of notches between two credit ratings on the 19-step scale, so that every later consumer uses the same scale, sign convention and validation.

## Traces to
AC-1 to AC-18 (plan.md). REQ-06-02. Clarifications C1 (scale, trim, case), C2 (RangeError for every invalid class), C3 (sign, integer), C4 (pure). Readiness CON-interface, CON-errors, ARC-async, DEL-docs, DEL-ci, TST-strategy, X-scale-immutability, X-error-message, X-test-coverage. CLAUDE.md.

## What to build
| File | Owner | Content |
|---|---|---|
| `src/ratings/notch.mjs` (new) | backend dev | Two named exports and no default export: `RATING_SCALE` and `notchChange(previous, current)`. It may have a private helper such as `indexOfRating(value, argName)`. JSDoc goes on both exports. |
| `test/ratings/notch.test.mjs` (new) | backend dev | `node:test` + `node:assert/strict` unit tests for AC-1 to AC-16. |

- `RATING_SCALE` is `Object.freeze([...])` holding the 19 C1 ratings, best first. Index 0 is `'AAA'`, 7 is `'BBB+'`, 10 is `'BB+'` and 18 is `'CCC-'`. Every sign is ASCII U+002B / U+002D.
- `notchChange(previous, current)` is synchronous and returns `index(current) - index(previous)`, an integer in -18..18.
- Validation order for each argument, `previous` first:
  1. `typeof v === 'string'`, else `RangeError`.
  2. `v.trim().toUpperCase()`.
  3. `RATING_SCALE.indexOf(key)`. If the result is -1, throw `RangeError`.
- The error message names the argument. It uses `typeof v` for non-strings and `JSON.stringify(v)` for unknown strings. The raw value is never concatenated or interpolated (X-error-message).
- JSDoc on `RATING_SCALE`:
  - it holds the 19 ratings, best first
  - it is frozen
  - the index is the notch position
- JSDoc on `notchChange`:
  - `@param {string} previous`, `@param {string} current`, `@returns {number}`
  - the sign convention: positive = downgrade, negative = upgrade, 0 = unchanged, range -18..18
  - trim and case-insensitive matching
  - `@throws {RangeError}` for non-strings (including String objects), empty or whitespace-only strings and unknown ratings, with `previous` checked first

## Acceptance criteria
1. **AC-1**: Given `import { RATING_SCALE } from '../../src/ratings/notch.mjs'`, when it is read, then:
   - `Array.isArray(RATING_SCALE) === true` and `RATING_SCALE.length === 19`
   - `assert.deepStrictEqual(RATING_SCALE, ['AAA','AA+','AA','AA-','A+','A','A-','BBB+','BBB','BBB-','BB+','BB','BB-','B+','B','B-','CCC+','CCC','CCC-'])` passes
   - every element has `typeof === 'string'` and matches `/^[ABC]{1,3}[+-]?$/` (ASCII `+` U+002B and `-` U+002D only)
2. **AC-2**: Given `RATING_SCALE`, then:
   - `Object.isFrozen(RATING_SCALE) === true`
   - in strict mode, `RATING_SCALE.push('CC')`, `RATING_SCALE[0] = 'X'`, `RATING_SCALE.length = 0` and `RATING_SCALE.reverse()` each throw `TypeError`
   - afterwards `RATING_SCALE[0] === 'AAA'`, `RATING_SCALE.length === 19` and `notchChange('AAA','CCC-') === 18`
3. **AC-3**: Given `('BBB+','BB+')`, when `notchChange` is called, then:
   - `result instanceof Promise === false`, `typeof result === 'number'` and `Number.isInteger(result) === true`
   - `Object.is(notchChange('A','A'), 0) === true` (+0, never -0)
4. **AC-4**: Given `('BBB+','BB+')`, when `notchChange` is called, then it returns `3`. This is a downgrade.
5. **AC-5**: Given `('BB+','BBB+')`, when `notchChange` is called, then it returns `-3`. This is an upgrade.
6. **AC-6**: Given `('A','A')`, when `notchChange` is called, then it returns `0`. This is unchanged.
7. **AC-7**: Given all 361 pairs `(i, j)` with `i, j ∈ 0..18`, when `notchChange(S[i], S[j])` is called, then:
   - it returns `j - i`, which is 0 for the 19 cases where `i === j`
   - `notchChange(S[i],S[j]) === -notchChange(S[j],S[i])`
8. **AC-8**: Given the 18 adjacent pairs (`AAA→AA+` … `CCC→CCC-`), then `notchChange(S[i],S[i+1]) === 1` and `notchChange(S[i+1],S[i]) === -1`.
9. **AC-9**: Given the ends of the scale, then:
   - `notchChange('AAA','CCC-') === 18` and `notchChange('CCC-','AAA') === -18`
   - no valid pair from AC-7 returns a value outside `-18..18`
10. **AC-10**: Given padded inputs, then they behave like the trimmed rating:
    - `(' BBB+ ','BB+')` returns `3`
    - `('BB+','\tBBB+\n')` returns `-3`
    - `(' A ','A')` returns `0`
    - `('\r\n AAA','CCC- ﻿')` returns `18`
11. **AC-11**: Given lower- or mixed-case inputs, then:
    - `('bbb+','BBB+')` returns `0`, `('bbb+','bb+')` returns `3` and `('Bb+',' bBb+ ')` returns `-3`
    - `('aaa','ccc-')` returns `18` and `('aA-','AA-')` returns `0`
    - for all 361 pairs, `notchChange(S[i].toLowerCase(), ' ' + S[j] + ' ') === j - i`
12. **AC-12**: Given `v ∈ {undefined, null, 0, 7, 3.5, NaN, true, false, 1n, Symbol('A')}`, then:
    - `notchChange(v,'A')` and `notchChange('A',v)` each throw `RangeError`, checked with `assert.throws(fn, RangeError)`
    - `notchChange()` and `notchChange('A')` also throw `RangeError`
13. **AC-13**: Given `v ∈ {new String('A'), new String('BBB+'), ['A'], [], {}, { toString() { return 'A'; } }, Object.create(null), () => 'A', new Date(0)}`, then each throws `RangeError` in both positions. Nothing is coerced, even when `String(v) === 'A'`.
14. **AC-14**: Given `v ∈ {'', ' ', '\t\n', ' '}`, then each throws `RangeError` in both positions.
15. **AC-15**: Given `v ∈ {'CC','C','D','NR','SD','BBB++','AAAA','BBB +','B B','A−','A＋','constructor','__proto__','toString'}`, then each throws `RangeError` in both positions.
16. **AC-16**: Given `(Symbol('x'), 42)`, `(null, 'CC')`, `('', Symbol('y'))` and `(Object.create(null), new String('A'))`, when `notchChange` is called, then each throws `RangeError` and never `TypeError`.
    - Code review confirms three things: `previous` is validated first, the message names the argument and uses `typeof` for non-strings, and there is no `'…' + v`, `${v}` or `String(v)`.
    - Tests assert only the error type.
17. **AC-17**: Given `src/ratings/notch.mjs`, then:

    - calls with valid and invalid inputs write nothing to stdout or stderr

## Edge cases
- **Type check before string methods.** `.trim()` or `.toUpperCase()` on a non-string would throw `TypeError` (fails AC-12). Coercion would make `new String('A')` or `['A']` valid (fails AC-13). Only `typeof v === 'string'` passes; `instanceof String`, `String(v)` and `v + ''` are not used.
- **Unsafe message building.** Concatenating or interpolating a Symbol or `Object.create(null)` throws `TypeError` and hides the `RangeError` (AC-12, AC-13, AC-16).
- **Lookup must use the array.** Use `RATING_SCALE.indexOf`. A plain object map or the `in` operator lets `'constructor'`, `'__proto__'` and `'toString'` match (AC-15).
- **Whitespace means `String.prototype.trim()` and nothing else.** NBSP and BOM are removed. Internal whitespace is not removed, so `'BBB +'` and `'B B'` are invalid.
- **Sign.** The result is `c - p`. `p - c` fails AC-4 and AC-5. Equal indexes give +0.
- **Missing or extra arguments.** A missing argument is `undefined` and throws `RangeError`. Arguments beyond two are ignored, for example `notchChange('A','A','x') === 0`.
- **Look-alike characters.** The Unicode minus U+2212, an en dash and the fullwidth plus U+FF0B are invalid, both in input and in the scale literal.
- **Both arguments invalid.** The error is raised for `previous` (AC-16).
- **Test discovery.** With no arguments, `npm test` (`node --test`) also finds `*.test.mjs` under `.work/` when it is run from the main checkout. AC-18 is therefore judged from the card's or job's checkout root.
