# T-01: ratings-lib: RATING_SCALE, notchChange and notchCalculator (REQ-06-02)

## User story
As a credit analyst using later Watchlist POC screens, I want to enter a previous and a current rating and get the signed notch change, its direction and the resulting WL, so that every external rating move is graded the same way. As the Indicator 12 developer (T-02), I want one shared `notchChange` and `RATING_SCALE`, so that the scale exists in one place only.

**What to build:** `src/ratings/notch.mjs`, ESM, named exports only, JSDoc on each export, no I/O:
- `RATING_SCALE`: frozen Array of the 19 C1 ratings, best first.
- `notchChange(previous, current)`: `index(current) − index(previous)`. Downgrade is positive, upgrade is negative, equal is `+0`.
- `notchCalculator(previous, current)`: returns `{ notches, direction, wl }` with exactly these keys.
  - `notches` is the same as `notchChange`.
  - `direction` is `"downgrade"` / `"upgrade"` / `"unchanged"` by sign.
  - `wl` is 2 if notches >= 3, 1 if notches === 2, otherwise 0.
- Input handling, for both arguments of both functions:
  - A non-string throws `RangeError`.
  - Otherwise apply `trim()` then `toUpperCase()` and look the value up in `RATING_SCALE`. A value not on the scale throws `RangeError`.

Unit tests go in `test/ratings/notch.test.mjs` (dev, TDD). QA tests go in `test/integration/ratings/*.test.mjs`.

## Edge cases
- **Scale ends and size:** AAA (index 0) and CCC- (index 18). The largest change is ±18, in both directions.
- **WL thresholds:**
  - Downgrades: 1 notch gives wl 0, exactly 2 gives wl 1, exactly 3 gives wl 2 (criteria 11–13).
  - Upgrades of 2 or 3 notches give wl 0. A `Math.abs` implementation fails this (criterion 14).
- **Never -0:** `notchChange` never returns `-0`, and neither does `notches` (`Object.is(x, 0)`).
- **Whitespace:** `trim()` strips leading/trailing `\t \n \r` space and ` `. Internal whitespace is kept, so `"BBB +"` and `"B B"` throw `RangeError`.
- **Values not on the C1 scale throw `RangeError`, with no mapping:** `"D"`, `"SD"`, `"NR"`, `"CC"`, `"C"`, `"AAA+"`, `"CCC--"`, `"Baa1"`, `"BBB+ (stable)"`.
- **Non-strings throw `RangeError` without being coerced:** `null`, `undefined`, a missing argument, `3`, `{}`, `["BBB"]`, `{ toString() { return "BBB"; } }`. The last two would pass if the code used `String(v)`, so they must be tested.
- **No partial result:** if either argument is invalid, the call throws. No default WL, no `null`, no `NaN`.
- **Error message (X-error-message):** the message names the bad input. This is checked in review; tests assert the type only.
- **Argument order matters:** `previous` comes first. `("BBB","BB")` = 3 while `("BB","BBB")` = -3.
