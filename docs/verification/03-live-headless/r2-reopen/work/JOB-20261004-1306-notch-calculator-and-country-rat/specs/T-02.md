# T-02: indicators-lib: Indicator 12 countryRatingChangeWl (REQ-03-12)

## User story
As a credit analyst, I want the country rating change (Indicator 12) graded as WL 0, 1 or 2 from the previous and current country rating I confirmed or edited, so that a sovereign downgrade raises the client's watchlist level by the REQ-03-12 thresholds.

**What to build:** `src/indicators/countryRating.mjs`, ESM, one named export with JSDoc, no I/O:
- `countryRatingChangeWl(previous, current)`:
  - `n = notchChange(previous, current)`, imported from `"../ratings/notch.mjs"`.
  - Return 2 if n >= 2, 1 if n === 1, otherwise 0.
- No scale of its own.
- No rating literals anywhere in the file, comments and JSDoc included.
- No use of `notchCalculator`.
- No try/catch: `RangeError` from `notchChange` propagates.
- Exactly 2 parameters, no module state.

Unit tests go in `test/indicators/countryRating.test.mjs` (dev, TDD). QA tests go in `test/integration/indicators/*.test.mjs`. This card depends on T-01 being merged.

## Edge cases
- **Thresholds differ from the calculator:**
  - 1-notch downgrade gives 1, where the calculator gives 0.
  - 2-notch downgrade gives 2, where the calculator gives 1.
  - 3 or more gives 2 in both.
  - Criteria 2 and 13 catch reuse of `notchCalculator().wl` or a shared helper.
- **Upgrades always give 0,** whatever their size (-1, -2, -18). A `Math.abs` implementation fails `("BBB-","BBB+")` and `("CCC-","AAA")`.
- **Scale ends:** AAA→AA+ = 1, CCC→CCC- = 1, AAA→CCC- = 2, CCC-→AAA = 0.
- **Invalid input:** all checks are delegated to `notchChange`. Every invalid or non-string value in either position throws `RangeError`. Nothing is caught, so no fallback 0.
- **Editable value (C7):**
  - The function has no override flag and no default parameters.
  - Extra arguments are ignored.
  - There is no cache or module state, so the same arguments always give the same result.
- **JSDoc:** describe the thresholds in words. Quoted rating examples would trip the AC-16 literal grep.
