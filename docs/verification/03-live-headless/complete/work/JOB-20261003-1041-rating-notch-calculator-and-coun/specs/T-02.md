# T-02: Indicator 12 countryRatingChangeWl (REQ-03-12) in src/indicators/countryRating.mjs

## User story
As a developer of the Watchlist POC (on behalf of the credit analyst reviewing a client's country), I want `countryRatingChangeWl(previous, current)` to return Indicator 12's WL from the analyst-confirmed previous and current country ratings, built on the shared `notchChange`, so that a country downgrade raises the client's watchlist level the same way everywhere.

## Traces to
AC-4 (indicator part), AC-5 (indicator part), AC-10, AC-11, AC-12, AC-13, AC-14, AC-15.
REQ-03-12 (and REQ-06-02 for the comparison in AC-12). Clarifications C1, C3, C4, C6, C7, C8. Readiness CON-errors, X-error-message, ARC-stack, DEL-ci, TST-strategy. Depends on T-01.

## What to build
- `src/indicators/countryRating.mjs` has one export, `countryRatingChangeWl(previous, current)`, with a short JSDoc:
  - `import { notchChange } from '../ratings/notch.mjs'`
  - `n = notchChange(previous, current)`
  - return the number `n <= 0 ? 0 : n === 1 ? 1 : 2`
- There is no scale, no validation of its own and no try/catch: the `RangeError` from `notchChange` propagates.
- No single-quoted rating literals anywhere in the file, JSDoc included.
- Do not modify `src/ratings/notch.mjs`. Report any defect found in it to T-01.

Who checks each criterion: **[U]** dev unit test in `test/indicators/*.test.mjs`. **[Q]** QA in `test/integration/countryRating*.test.mjs`, or in `test/integration/purity*.test.mjs` for criterion 8. **[CMD]** a command whose output is attached as evidence.

## Acceptance criteria
1. **(AC-4, indicator part) Trim and case [U+Q].**
   - `countryRatingChangeWl(' a ', 'a-') === 1`.
   - `countryRatingChangeWl('A', '\tA-\n') === 1`.
   - `countryRatingChangeWl('bbb+', 'BB+') === 2`.
   - `countryRatingChangeWl('aaa', 'ccc-') === 2`.
   - For every `r` in `RATING_SCALE` (imported from `src/ratings/notch.mjs`): `countryRatingChangeWl(r.toLowerCase(), ' ' + r + ' ') === 0` and `countryRatingChangeWl(' ' + r + ' ', r.toLowerCase()) === 0`.

2. **(AC-5, indicator part) Invalid input throws RangeError [U+Q].**
   - Given each value `v` in the same 23-value invalid list as T-01 criterion 5:
     - strings: `''`, `'   '`, `'D'`, `'SD'`, `'CC'`, `'C'`, `'AAA-'`, `'A++'`, `'BBB++'`, `'BBB +'`, `'B B B+'`, `'Baa1'`, `'BBB−'`, `'BBB+ (neg)'`
     - non-strings: `null`, `undefined`, `7`, `0`, `NaN`, `true`, `{}`, `['BBB+']`, `{ toString: () => 'BBB+' }`
   - When it is called as `countryRatingChangeWl(v, 'BBB')`, `countryRatingChangeWl('BBB', v)` and `countryRatingChangeWl(v, v)` (69 calls).
   - Then each satisfies `assert.throws(…, RangeError)`. The error is never a `TypeError`, and no WL is returned.
   - And `countryRatingChangeWl('BBB+')` and `countryRatingChangeWl()` throw `RangeError`.
   - The error type only is asserted, never the message (X-error-message).

3. **(AC-10) Downgrade WL [U+Q].**

   - Each result has `typeof result === 'number'`, so `'1'` would fail.

4. **(AC-11) Upgrade or unchanged gives 0 [U+Q].**

5. **(AC-12) Deliberately different from the calculator [U+Q, QA sweep].**

   - `countryRatingChangeWl('A','A-') === 1`: the pre-filled `A` was edited to `A-` and the confirmed value is passed.

   - `countryRatingChangeWl.length === 2`. Together with T-01, QA also asserts `notchChange.length === 2` and `notchCalculator.length === 2` through the public exports.

## Edge cases
- **Errors pass through unchanged.** No try/catch or wrapping. Anything `notchChange` rejects must reach the caller as the same `RangeError`, including `Symbol('A')`, `10n`, `Object.create(null)` and `new String('A')`. Dev unit tests should include these four extras (C1 "anything else"). QA may.
- **Threshold boundaries.**
  - n = 0 gives 0, n = 1 gives 1, n = 2 gives 2, n = −1 gives 0, n = 18 gives 2 and n = −18 gives 0.
  - There is no WL 3 or 4 from this indicator.
  - Do not "harmonise" with the calculator (C6). It differs on purpose at n = 1 and n = 2.
- **Default grades.**
  - A country falling to `'D'`, `'SD'` or `'RD'` cannot be scored. It throws `RangeError` (C1; the business accepted this for this slice, see plan Risks).
  - No test may expect a WL for it.
- **Ambiguous whitespace.** Same rule as T-01: trim semantics. `' A\r'` is not asserted by any AC.
- **JSDoc and the grep.** Examples in comments must not use single-quoted `'AAA'`, `'BBB+'` or `'CCC-'`, or the AC-13 grep fails. Prose or double quotes are allowed. Better, leave examples out.
- **Do not run the full suite from inside a test.** A test that spawns `node --test` from the repo root would rediscover and rerun itself without end. Criterion 8(e) is a command run by QA or Michael, never an assertion inside a test file.
- **Helper files under `test/`.** Node 22's default discovery runs any `.mjs` under a `test/` directory. Keep helpers inside the `*.test.mjs` files (criterion 8(d)).
- **Silence check inside the test process.** Use the child-process approach in criterion 8(c). Patching `process.stdout.write` inside a `node --test` file is fragile because the runner reports over stdout.
