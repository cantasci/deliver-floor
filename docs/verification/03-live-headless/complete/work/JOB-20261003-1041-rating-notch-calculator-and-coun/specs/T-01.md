# T-01: Rating scale, notchChange and notchCalculator (REQ-06-02) in src/ratings/notch.mjs

## User story
As a developer building other parts of the Watchlist POC (and, through them, the credit analyst), I want one shared rating scale, a signed notch count and a notch calculator that gives a WL using the Indicator 13 thresholds, so that a rating change is counted and graded the same way everywhere.

## What to build
- `src/ratings/notch.mjs` exports exactly `RATING_SCALE`, `notchChange` and `notchCalculator`, with short JSDoc on each.
- Validation lives in one non-exported helper (for example `toIndex(value, paramName)`):
  - If `typeof value !== 'string'`, it throws `RangeError` before any string method runs.
  - Otherwise it applies `value.trim().toUpperCase()` and looks the result up in `RATING_SCALE`. If it is not there, it throws `RangeError`.
- `notchCalculator` gets its validation by calling `notchChange`.
- The module has no imports, no I/O and no output.

Who checks each criterion: **[U]** dev unit test in `test/ratings/*.test.mjs`. **[Q]** QA integration test in `test/integration/notch*.test.mjs`, black-box through `import … from '../../src/ratings/notch.mjs'`. **[U+Q]** both. **[CMD]** a command check whose output is attached as evidence.

The index reference table is in plan.md: AAA=0, AA+=1, AA=2, AA-=3, A+=4, A=5, A-=6, BBB+=7, BBB=8, BBB-=9, BB+=10, BB=11, BB-=12, B+=13, B=14, B-=15, CCC+=16, CCC=17, CCC-=18.

## Edge cases
- **Signed zero.**
  - Compute `idx(current) - idx(previous)` and never negate a difference.
  - `assert.strictEqual` and `assert.deepStrictEqual` compare with `Object.is`, so a `-0` makes `strictEqual(x, 0)` and the `{ notches: 0 … }` deep-equal fail. Keep it that way, because that is the guard.
- **Non-string look-alikes** must be rejected before any coercion:
  - `['BBB+']`: `String()` gives `'BBB+'`.
  - `{ toString: () => 'BBB+' }`.
  - `new String('BBB+')`: typeof is `'object'`, so it is rejected (C1 "anything else"; card rule `typeof !== 'string'`).
- **Building the message must never throw.**
  - `Symbol('BBB+')`, `10n` and `Object.create(null)` must each throw `RangeError`, not the `TypeError` that `` `${v}` `` or `JSON.stringify(v)` would raise.
  - These values are not in the AC-5 list but fall under C1 "anything else". Dev unit tests should include them. QA may.
- **Whitespace.**
  - Only leading and trailing whitespace is trimmed, using `String.prototype.trim` semantics.
  - Inner whitespace is rejected: `'BBB +'` and `'B B B+'` throw.
  - `trim()` also removes `\r`, NBSP and BOM, so `' BBB+\r\n'` is accepted. This is not asserted by any AC. Do not write a QA test that expects either result.
- **Lookalike characters.** `'BBB−'` (Unicode minus) and full-width letters are rejected. Only ASCII `+` and `-` are valid.
- **Ratings outside C1.** `'D'`, `'SD'`, `'RD'`, `'CC'`, `'C'`, Moody's `'Baa1'`, outlooks `'BBB+ (neg)'` and agency prefixes all throw `RangeError`.
- **Order when both arguments are invalid.** This is not part of the contract. Assert the type only.
- **Extra arguments.** `notchChange('A','A-','x')` is not part of the contract (JS ignores extras). Do not test it either way.
- **Freeze test isolation.** Put the mutation attempts (criterion 2) in their own test file, for example `test/ratings/scale-freeze.test.mjs`. `node --test` runs each file in its own process, so if the array were not frozen during the red phase, the corrupted scale would not break other tests.
