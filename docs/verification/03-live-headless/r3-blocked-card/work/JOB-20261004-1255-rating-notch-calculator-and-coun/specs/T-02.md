# T-02: Indicator 12 country rating change WL: countryRatingChangeWl (REQ-03-12)

## User story
As a credit analyst (through POC screens built later) and as a developer of the indicator engine, I want the Watchlist level for a change in the client's country rating, so that a 1-notch country downgrade gives WL 1, a downgrade of 2 or more notches gives WL 2, and an upgrade or no change gives WL 0.

## Edge cases
- Exact threshold edges: n=0 gives 0, n=1 gives 1 and n=2 gives 2. n=-1, 3 and 18 also fall in the right band (-1 gives 0, 3 and 18 give 2).
- Ends of the scale: `("AAA","AA+") → 1`, `("CCC","CCC-") → 1`, `("AAA","CCC-") → 2`, `("CCC-","AAA") → 0`, `("AAA","AAA") → 0`, `("CCC-","CCC-") → 0`.
- The result must never be `-0`, `null`, `undefined`, a string or a Promise. It must be one of the numbers 0, 1 or 2.
- Non-string input (`null`, `undefined`, `7`, `{}`, `[]`, `new String("AAA")`) throws `RangeError`, never `TypeError`. Validation is only the one in `notchChange`; there is no second validation path.
- Inner whitespace (`"BBB +"`, `"B B"`) and the look-alike minus characters U+2212 and U+2013 throw `RangeError`. Unicode whitespace at either end (NBSP) is removed (X-trim).
- No state between calls: no caching and no module-level mutable variables. Interleaved calls in any order give the same results (AC-12).
- The module must not use `notchCalculator().wl`, because those are the Ind. 13 thresholds (C6).
- The module must not change `src/ratings/notch.mjs`, which T-01 owns.
