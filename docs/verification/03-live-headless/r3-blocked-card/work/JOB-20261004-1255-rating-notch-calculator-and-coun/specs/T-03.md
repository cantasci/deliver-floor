# T-03 (replaces T-01): Notch calculator module: RATING_SCALE, notchChange, notchCalculator (REQ-06-02)

## User story
As a developer building other Watchlist POC parts (and Indicator 12 in T-02), I want a pure, synchronous notch calculator with a fixed 19-step rating scale, so that I can turn a previous and current rating into a signed notch change, a direction and a WL using the Ind. 13 thresholds.

## Edge cases
- Ends of the scale: the pairs AAA→AAA, CCC-→CCC-, AAA→CCC- (18) and CCC-→AAA (-18) must work. No index is ever out of range.
- Non-string input: `null`, `undefined`, `7`, `{}`, `[]`, `true` and `new String("AAA")` must throw `RangeError`. The `typeof value === "string"` check comes before `.trim()`, so `null.trim` can never produce a `TypeError`.
- Whitespace only (`""`, `"   "`, `"\t\n"`) is empty after the trim and throws `RangeError`.
- Inner whitespace is not removed: `"BBB +"` and `"B B"` throw `RangeError`.
- Unicode whitespace at either end (NBSP ` `, ` `) is removed by `trim()` and is accepted (X-trim).
- Look-alike characters: `"BBB−"` (minus sign) and `"BBB–"` (en dash) throw `RangeError`. Only the ASCII hyphen-minus is accepted.
- Ratings outside the 19-step scale or in other notations throw `RangeError`: `"D"`, `"SD"`, `"NR"`, `"WR"`, `"Baa1"`, `"AAA+"`, `"CCC--"`, `"BBB+ (neg)"`.
- Both arguments invalid: `RangeError` is thrown. The message text is not asserted. Per X-error-message the message should name `previous` or `current` and the bad value, but tests check only the type.
- The result for an unchanged rating must be `+0`, never `-0`, in both `notchChange` and `notchCalculator().notches`.
- Repeated calls give the same result, and calls do not change `RATING_SCALE`.
