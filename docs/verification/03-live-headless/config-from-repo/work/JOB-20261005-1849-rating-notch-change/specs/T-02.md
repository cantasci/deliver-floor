# T-02: ratings-lib: RATING_SCALE + notchChange(previous, current) in src/ratings/notch.mjs with unit tests

## User story
As a developer building Indicators 11, 12 and 13 and the later REQ-06-02 notch calculator, I want a pure module that counts the signed notches between two credit ratings, so that every indicator uses the same rating scale and the same sign rule (a downgrade is positive, an upgrade is negative).

## Traces to
AC-1 to AC-14 in plan.md. Source: REQ-06-02 (part), with clarifications C1, C2, C3 and C4 and the readiness decisions.

## Acceptance criteria

Every criterion below reads: **Given** the module `src/ratings/notch.mjs` is imported (and the stated arguments or tampering), **When** `notchChange` is called or `RATING_SCALE` is inspected, **Then** the stated result holds (the value, or the error type).

Scale indexes (0 = best): AAA 0, AA+ 1, AA 2, AA- 3, A+ 4, A 5, A- 6, BBB+ 7, BBB 8, BBB- 9, BB+ 10, BB 11, BB- 12, B+ 13, B 14, B- 15, CCC+ 16, CCC 17, CCC- 18.

Contract: `src/ratings/notch.mjs` has named exports only and no default export. It exports exactly two names, `RATING_SCALE` and `notchChange`. Internal helpers are not exported. Both exports have JSDoc. For `notchChange` the JSDoc needs `@param {string} previous`, `@param {string} current`, `@returns {number}` and `@throws {RangeError}`.

1. **AC-1 (the scale).**
   - `assert.deepStrictEqual(RATING_SCALE, ['AAA','AA+','AA','AA-','A+','A','A-','BBB+','BBB','BBB-','BB+','BB','BB-','B+','B','B-','CCC+','CCC','CCC-'])` passes; length 19; [0] 'AAA'; [18] 'CCC-'; indexOf('BBB+') 7; indexOf('BB+') 10; Array.isArray true; new Set size 19; Object.isFrozen true.
   - All hyphens are ASCII U+002D and all plus signs are ASCII `+`.
   - `RATING_SCALE.push('D')` or `RATING_SCALE[0] = 'X'` throws `TypeError`; afterwards length 19, [0] 'AAA' and `notchChange('BBB+','BB+') === 3`.
2. **AC-2.** `notchChange('BBB+', 'BB+')` returns `3`.
3. **AC-3.** `notchChange('BB+', 'BBB+')` returns `-3`.
4. **AC-4 (unchanged).** `notchChange('A','A')` returns `0` and `Object.is(result, 0)` is true (not `-0`). For every `r` in `RATING_SCALE`, `notchChange(r, r) === 0`. The result is computed as exactly `indexCurrent - indexPrevious`.
5. **AC-5 (adjacent steps).** `('AAA','AA+')` 1; `('A-','BBB+')` 1; `('BBB-','BB+')` 1; `('B-','CCC+')` 1; `('CCC','CCC-')` 1; `('BB+','BBB-')` -1.
6. **AC-6 (extremes).** `('AAA','CCC-')` 18; `('CCC-','AAA')` -18.
7. **AC-7 (every pair).** For all 361 pairs `(i, j)`: result `=== j - i`; `typeof` 'number'; `Number.isInteger`; within -18..18; not a Promise; same value on a second call; for `i !== j`, `notchChange(a, b) === -notchChange(b, a)`.
8. **AC-8 (case-insensitive; toUpperCase, never toLocale*).** `('bbb+','bb+')` 3; `('Bbb+','bB+')` 3; `('aaa','ccc-')` 18; `('a','A')` 0.
9. **AC-9 (String.prototype.trim()).** `('  BBB+ ', '\tBB+\n')` 3; `('  bbb+ ', 'BB+')` 3; `(' A﻿', 'A')` 0 (write with escapes).
10. **AC-10 (unknown → RangeError).** For each x of `'D'`, `'C'`, `'CC'`, `'NR'`, `'AAA-'`, `'AAA+'`, `'BBB +'`, `'B B'`, `'BBB++'`, `'Baa1'`, `'AA−'`, `'АAA'`: `notchChange(x, 'A')` and `notchChange('A', x)` throw RangeError.
11. **AC-11 (empty / whitespace-only → RangeError).** `''`, `'   '`, `'\n\t'` in either position throw RangeError.
12. **AC-12 (non-string → RangeError, never TypeError).** For each x of `undefined`, `null`, `7`, `0`, `NaN`, `7n`, `true`, `{}`, `[]`, `['A']`, `new String('A')`, `{ toString: () => 'A' }`, `Symbol('A')`, `() => 'A'` in either position: `err instanceof RangeError`. `notchChange()`, `notchChange('A')` and `notchChange(null, 'D')` also throw RangeError. The `typeof value !== 'string'` check comes first; the message names only the argument and never puts the raw value into a template string, `+`, `String()` or `JSON.stringify`. The message text is not asserted.
13. **AC-13 (pure, silent, dependency-free).** A child `node -e` that imports the module and calls `notchChange('A','B')` (9) and a caught `notchChange('D','A')` has empty stdout, empty stderr, exit 0. `notch.mjs` has no `import` statement, no `import()`, no `require`, no `console.`, no `process.`. `package.json` has no `dependencies` or `devDependencies`.
14. **AC-14 (tests and verification).** `npm test` exits 0 on Node 18+. `test/ratings/notch.test.mjs` imports `node:test` and `node:assert/strict`, has at least one `test()` per AC-1..AC-13 with the AC id in its name, and a test for each C2 rejection class (unknown, '', whitespace-only, undefined, null, number, new String('A'), Symbol). Node 18 APIs only (no toSorted, toReversed, with, Object.groupBy).

## Edge cases
- Same rating: `+0`, never `-0`, for all 19 ratings, also with padded or lower-case input such as `notchChange(' a ', 'A')`.
- Whitespace inside a rating is never removed: `'BBB +'` and `'B B'` throw. `trim()` removes U+00A0, U+FEFF, U+3000, `\t`, `\n`, `\r` at the ends only.
- Lookalikes stay unknown: U+2212 minus, U+2013 en dash, Cyrillic А, full-width `Ａ`.
- Both arguments invalid → still RangeError. Errors are thrown synchronously, never a rejected Promise.
- Extra arguments are not specified and not tested.

## QA integration tests: test/ratings/notch.qa.test.mjs
These test the module the way a consumer uses it and do not repeat the dev's unit tests one-to-one. The file runs under `npm test`, so it must be deterministic, fast and silent, Node 18 APIs only.

1. **Import from outside (AC-1).** Spawn `process.execPath` with `['--input-type=module', '-e', script]`, `cwd: os.tmpdir()`; the script imports `pathToFileURL(<abs src/ratings/notch.mjs>).href` and writes `JSON.stringify({ keys: Object.keys(m).sort(), hasDefault: 'default' in m, r: m.notchChange('BBB+','BB+'), frozen: Object.isFrozen(m.RATING_SCALE) })`. Expect `{"keys":["RATING_SCALE","notchChange"],"hasDefault":false,"r":3,"frozen":true}`, status 0, stderr ''.
2. **361-pair matrix against an independent oracle (AC-7, AC-4, AC-8, AC-9).** Hard-code the index table as a literal in the QA file. For all 19x19 pairs assert `notchChange(p, c) === idx[c] - idx[p]` in four spellings (as written; `p` lower-case with `c` as `'　' + c + '\r\n'`; `p` padded `'  '` with `c` first-character lower-case; both lower-case padded with `'\t'`). `Object.is(result, 0)` on all diagonal entries in every spelling. `notchChange(a,b) + notchChange(b,c) === notchChange(a,c)` for all 6,859 triples.
3. **Tamper with the frozen scale, then use it (AC-1, AC-7).** Each of `push('D')`, `pop()`, `splice(0,1)`, `sort()`, `reverse()`, `fill('X')`, `length = 0`, `[0] = 'X'`, `delete [0]`, `Object.defineProperty(RATING_SCALE, 0, { value: 'X' })` throws `TypeError`. Reverse and clear a consumer copy `[...RATING_SCALE]`. After that `RATING_SCALE` still deep-equals the 19-entry literal, the 361-pair matrix still matches the oracle, and `notchChange('AAA','CCC-') === 18`.
4. **Silent and no I/O, in a child process (AC-13).** Child process with `--input-type=module`, `cwd: os.tmpdir()`: replace `console.*` and `process.stdout/stderr.write` with counters (keep the original stdout write), import by file URL, run all 361 pairs and every invalid value of AC-10/11/12 in both positions in try/catch recording RangeError, finally write `{"calls":0,"allRange":true}`. Second run: the plan's literal one-liner → stdout '', stderr '', status 0.
5. **package.json untouched (AC-13).** No `dependencies`, `devDependencies`, `peerDependencies`, `optionalDependencies`; `scripts.test === 'node --test'`; `type === 'module'`; no `package-lock.json`, no `node_modules/`. Do not compare against git (the QA worktree's base is the job branch; skip any git-based check).
6. **Error contract as a consumer sees it (AC-10/11/12).** For `'D'`, `''`, `Symbol('A')`, `new String('A')`, `null`: synchronous catch, `err instanceof RangeError`, `err.name === 'RangeError'`. A valid call does not return a thenable. The message is not asserted.

AC-14 is evidence at the gate, not part of the QA file.
