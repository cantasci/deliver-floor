# T-01: Rating scale, notchChange and notchCalculator (REQ-06-02)

## User story
As a credit analyst, working through the POC modules that import this library, I want to give a previous and a current rating and get back the signed notch change, its direction and the resulting WL, so that a downgrade raises the Watchlist level by the confirmed thresholds (C2, C3, C6).

## What to build
- `src/ratings/notch.mjs` exports exactly three names:
  - `RATING_SCALE`: a frozen array of the 19 C1 ratings, best first. Index: AAA 0, AA+ 1, AA 2, AA- 3, A+ 4, A 5, A- 6, BBB+ 7, BBB 8, BBB- 9, BB+ 10, BB 11, BB- 12, B+ 13, B 14, B- 15, CCC+ 16, CCC 17, CCC- 18.
  - `notchChange(previous, current)`: returns the integer `index(current) − index(previous)`.
  - `notchCalculator(previous, current)`: returns a new plain object `{notches, direction, wl}`.
- Validation lives in one private helper: non-string -> `RangeError`; otherwise `trim()`, `toUpperCase()`, lookup in a private `Map`; no match -> `RangeError`.
- The file has no imports. Unit tests go in `test/ratings/notch.test.mjs`.

## Edge cases
- Scale ends: AAA→CCC- = +18, CCC-→AAA = −18; equal ratings give `+0`, never `-0`.
- WL boundaries at notches −1 / 0 / 1 (wl 0), 2 (wl 1), 3 (wl 2).
- Case-folding with `toUpperCase()`, not `toLocaleUpperCase()`; `"aaa-"` folds to `"AAA-"` (not on scale) -> RangeError.
- Whitespace removed by `trim` is valid (space, `\t`, `\n`, ` `, `　`, `﻿`); inner whitespace, whitespace-only and `"​BBB+"` (zero-width space, not trimmed) throw RangeError.
- Look-alikes (U+2212 minus, en dash, full-width letters) throw RangeError.
- Type check BEFORE `.trim()`: null/undefined must give RangeError, not TypeError. No coercion of 7, true, ["AAA"], {}, new String("AAA").
- Private Map lookup, so prototype keys never match.
