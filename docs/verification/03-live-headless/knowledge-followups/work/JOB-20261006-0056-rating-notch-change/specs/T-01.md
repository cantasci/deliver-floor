# T-01: ratings-lib: add src/ratings/notch.mjs (RATING_SCALE + notchChange) with unit tests

## User story
As the developer of Indicators 11, 12 and 13 and the REQ-06-02 notch calculator, I want one pure, synchronous function that gives the signed notch change between a previous and a current credit rating, so that every indicator counts downgrades and upgrades the same way, on one fixed scale.

## Traces to
AC-1 to AC-17 of plan.md. REQ-06-02 (part). Readiness decisions: C1, C2, C3, C4, Contract, CON-interface, CON-errors, ARC-async, X-export-style, X-scale-immutability, X-input-normalisation, X-error-message, TST-strategy, DEL-ci, and CLAUDE.md.

## What to build
- `src/ratings/notch.mjs` (new) has exactly two named exports.
  - `RATING_SCALE`: a frozen array of the 19 ratings, best first.
  - `notchChange(previous, current)`: synchronous. It returns `index(current) - index(previous)`.
- `test/ratings/notch.test.mjs` (new) tests it with `node:test` and `node:assert/strict`.
- No other files change. `package.json` is not edited.

Index reference: AAA=0, AA+=1, AA=2, AA-=3, A+=4, A=5, A-=6, BBB+=7, BBB=8, BBB-=9, BB+=10, BB=11, BB-=12, B+=13, B=14, B-=15, CCC+=16, CCC=17, CCC-=18.

## Edge cases
- **Validation order:** `previous` is validated completely (type, trim, match) before `current` is looked at. Extra arguments are ignored: `notchChange('A','B','junk') === 9`.
- **Type check:** only `typeof x === 'string'` counts as a string. String objects, arrays such as `['A']`, and functions are rejected, even when they would turn into a valid rating.
- **Safe error message:** building the message must not throw for any value. A template literal on `Symbol('A')` or `Object.create(null)` throws `TypeError`, and so does `JSON.stringify(7n)`. The thrown error must still be a `RangeError` for these values.
- **Case-folding:** use `toUpperCase()`, which does not depend on locale. Do not use `toLocaleUpperCase` and do not apply Unicode normalisation.
- **Result:** for valid input the result is always an integer in `[-18, 18]`, never `NaN`, and the module has no fallback value.
- **Purity:** calls never mutate `RATING_SCALE`, and repeated calls give identical results.
- **Node version:** nothing newer than Node 18 may be used, for example `toSorted` or `Object.groupBy`. The test file must be found by bare `node --test`.
