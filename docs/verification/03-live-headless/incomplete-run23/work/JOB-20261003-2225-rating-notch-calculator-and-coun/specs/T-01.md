# T-01: Rating scale, notchChange and notchCalculator in src/ratings/notch.mjs (REQ-06-02)

## What to build
Create `src/ratings/notch.mjs`, a pure ESM module with no I/O. It exports exactly these three names:
- `RATING_SCALE`: the 19 grades from C1, best first, frozen with `Object.freeze` (X-scale-shape).
- `notchChange(previous, current)`: returns `index(current) - index(previous)` as a signed integer. Positive is a downgrade, negative is an upgrade, and the unchanged case is `+0`, never `-0`.
- `notchCalculator(previous, current)`: returns a new plain object `{ notches, direction, wl }` on every call. `notches` equals `notchChange` (signed, per CON-interface). `direction` is `"downgrade"`, `"upgrade"` or `"unchanged"`. `wl` follows the Indicator 13 thresholds: `d<=1` gives 0, `d===2` gives 1, `d>=3` gives 2 (X-wl-rules).

Both functions share one internal normaliser that is not exported. An input is valid only if it is a primitive string that, after `trim()` and upper-casing, equals one of the 19 grades. Anything else throws `RangeError`. `previous` is checked first. Only the error type is contract (CON-errors, X-error-message).

Unit tests go in `test/ratings/notch.test.mjs` and use `node:test` and `node:assert/strict`.

## User story
As a credit analyst (through the POC modules that import this helper), I want to enter a previous and a current rating and get back the notch change, its direction and the resulting Watchlist level, so that I can see at once how serious a rating move is.

## Edge cases
- Extremes: `AAA→CCC-` = +18 and `CCC-→AAA` = -18 are the largest magnitudes. Neither is clamped.
- Unchanged: every one of the 19 `(g, g)` pairs gives `+0` from both functions, never `-0`. Criteria 9, 24 and 25 check this, and the 361-pair loop should also check it with `Object.is`.
- Trimming uses `String.prototype.trim()` only. Inner whitespace is not removed, so `"BBB +"` is invalid.
- Case folding: `"bbb+"`, `"Bbb+"` and `"BBB+"` are all valid.
- Look-alike characters are not normalised. `"BBB−"` (Unicode minus), `"AAA+"` and `"CCC--"` are invalid.
- Notations outside the scale (`"D"`, `"NR"`, `"SD"`, `"Baa1"`) are rejected and not mapped.
- Non-strings (`null`, `undefined`, `3`, `{}`) and missing arguments throw `RangeError`, not `TypeError`.
- Boxed strings (`new String("BBB")`): `RangeError`. Not an AC, a test is optional.
- Validation order: `previous` is checked before `current`. Message text is not asserted.
- `RATING_SCALE` must not be mutable by consumers. The returned object is not frozen, but it is fresh on every call.
