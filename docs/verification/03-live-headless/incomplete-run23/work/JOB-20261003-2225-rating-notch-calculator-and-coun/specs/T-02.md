# T-02: Indicator 12 countryRatingChangeWl in src/indicators/countryRating.mjs (REQ-03-12)

## What to build
Create `src/indicators/countryRating.mjs`, a pure ESM module with no I/O. It exports exactly one name:
- `countryRatingChangeWl(previous, current)`, which returns `0 | 1 | 2`.

The module does `import { notchChange } from "../ratings/notch.mjs"` and computes `d = notchChange(previous, current)`. It then returns `0` when `d<=0`, `1` when `d===1` and `2` when `d>=2` (Indicator 12 thresholds, X-wl-rules). These thresholds differ from `notchCalculator().wl`. The function must not reuse the calculator's `wl`.

The function has exactly two declared parameters and no override or options argument (C7). It is synchronous and returns a primitive number. Invalid input is handled by the `RangeError` that `notchChange` already throws; the module does not validate again and does not catch the error. `src/ratings/**` must not be modified.

Unit tests go in `test/indicators/countryRating.test.mjs` and use `node:test` and `node:assert/strict`.

## User story
As a credit analyst, I want the change in the client's country rating (the values I confirmed or edited) turned into an Indicator 12 Watchlist level, so that a country downgrade raises the client's watchlist signal by the agreed amount.

## Edge cases
- The 1-notch boundary is where the two mappings differ: Indicator 12 gives 1 and the calculator gives 0. Any shared threshold table fails criteria 5, 6 and 15.
- The 2-notch boundary also differs: Indicator 12 gives 2 and the calculator gives 1 (criteria 7 and 15).
- Largest moves: `AAA→CCC-` gives 2 (capped). `CCC-→AAA` gives 0.
- The result is always one of the literals `0`, `1` or `2`; never `-0`, `NaN`, `undefined`, or an unclamped `d`.
- Normalisation and validation come only from `notchChange`. `"SD"` and boxed strings are rejected with `RangeError` through `notchChange` (not asserted as an AC).
- The `RangeError` from `notchChange` must reach the caller unchanged: not caught, wrapped or turned into a default WL.
- A third argument is ignored: `countryRatingChangeWl("BBB+","BBB",2) === 1` (optional; supports C7).
